验收日期：2026-11-27 至 2026-11-28。范围是本机版本，未推送 GitHub。

## 已实现

- 飞书回复共用文本规范，去掉常见 Markdown 包装，保留数值、比较符号和链接。平台自己的卡片样式继续使用飞书支持的格式。
- 普通任务通过 SDK 单独返回 `{ reply }`，限制 240 字；聊天、动态任务计划仍使用各自原有结构。摘要说明结果和重要限制，工具调用、代码、文件清单与内部交接保留在项目记录和工作区。团队包的完整结束输出同步到 `context/task-history.json`，写入与状态保存串行，避免并行任务覆盖。
- 原网页团队的结果卡去掉工具和 token 明细，进度卡保留当前活动、用时与操作。任务阶段、权限、文件交付检查与人工确认关口保持原样。
- 标准扫码程序使用赛博朋克风格的数字生命身份页，展示名称、职责和能力；能力来自 Agent 任务，不把人的确认/验收当成 Agent 能力。已有角色复用原身份，可从工作台“查看数字同事”进入。
- 页面原位更新扫码回执，保留角色选择和键盘焦点；区分身份创建和团队连接。部分失败不会阻止其他角色继续扫码。没有新建重复机器人。

## 模型切换

原火山账户对 Kimi、GLM、DeepSeek 三种替代模型均返回账户欠费 403，不能据此判断各模型资源包额度已耗尽。

按用户新提供的配置，切换至 `https://opencode.ai/inference/go/anthropic`，模型 `deepseek-v4.1-flash`。首次请求因缺会话头被拒，已为 setup 检查补齐客户端标识和会话头；SDK 使用原生 Claude Code 会话头。随后用户在 OpenCode 工作区启用 Global，接口连通、实际工具调用和结构化输出均通过。接入方式见 [OpenCode 官方 Claude Code 文档](https://opencode.ai/docs/console/harnesses/claude-code/)，区域要求见 [Go 说明](https://opencode.ai/docs/console/go/#enable-restricted-models)。

## 对抗检查

已修复三类可复现问题：手机角色列表撑宽导致整页缩小；某角色在生成二维码前失败导致其他角色的页面不打开；按逗号拆摘要可能留下半句内部说明甚至改变否定关系。摘要现在保留完整句子，并采用独立结构化回复出口，不能把“提交”当成“验收通过”。

角色文本以 `textContent` 写入，初始脚本数据转义 `<`，授权链接只接受 HTTPS；已创建状态只来自真实注册回执，团队就绪只来自连接完成。动态计划的结构、目录权限和人工关口没有放宽。

Grok CLI 本轮只读审查未返回结果，已终止，不计入通过证据。上述对抗检查与修复由 Codex 实际执行。
