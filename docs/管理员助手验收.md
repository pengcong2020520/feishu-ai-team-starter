# 管理员助手与真实项目验收

本轮以一个真实「每日待办」项目验证需求澄清、PRD、设计、开发、走查、打回修改和交付，同时验证管理员私聊背后的处理链路。使用真实模型、Git 工作副本、运行中的团队服务和飞书发送接口；项目数据和账号标识不放入仓库。

## 测试方式

真实飞书私聊收消息、状态卡和测试卡按钮已有客户端验证。本轮还发送了一条真实私聊调度请求，确认管理员按当时项目状态回应。完整项目从工作台提需求开始，与飞书共用编排，群里保留来源。

随后通过标准输入把测试事件送进正式的 `im.message.receive_v1` 和 `card.action.trigger` 处理器。下游使用真实管理员模型、真实飞书发卡、真实 Git 提交与团队进程；没有额外开放测试控制端口，也没有让同一个机器人建立两处连接。这部分属于处理器驱动的集成测试，不冒充飞书客户端发送或真人点击。

网页交互使用独立无头 Chromium 验证，覆盖真实 DOM、回车事件、原生确认框、刷新和存储异常，并检查桌面和手机截图。测试不需要飞书保持前台。

## 本轮发现并修复的问题

- 管理员首次修改时，工作副本尚未初始化，模型找不到应修改的文件。现在在非只读管家任务开始前准备工作副本；只读诊断不创建副本。真实模型在全新仓库中通过正式助手入口完成读取、修改、提交和测试，文字改动生效。
- 工作副本有草稿时，线上出现其他提交或撤销，原来的压提交操作可能把旧内容覆盖回去。现在提交前检查祖先关系，不匹配则保留草稿并停止提交。回归覆盖外部更新和撤销两种情况。
- 没有进行中的项目时，工作台产品经理已选「新需求」，输入框和发送按钮却被禁用。管理员在工作副本修正这一行条件，签字上线后无头浏览器确认产品经理可输入，设计和程序员仍禁用。
- 飞书 SDK 默认错误日志会展开含请求头的请求对象。团队、管理员与安装流程统一使用受限 SDK 日志；用真实权限不足响应验证，只保留错误码，不输出原始请求。业务层仍保留用于定位问题的 code/msg。

## 真实项目与管理员运营

每日待办按正式流程完成澄清、PRD、线框和主题、开发与走查。首版发现空筛选下新增不可见、字数显示和校验不一致、手机勾选与删除触控区偏小；管理员代为打回并转交程序员，修改后自动回归走查。独立截图复核又发现手机输入框被纵向 flex 压到 21px，继续打回修复。最终 26 项浏览器检查通过，包含原生删除确认与取消、完成筛选、刷新持久化、纯文本输入、长度边界、手机布局、状态直达及存储不可用时的内存操作。

主动停下程序员后，管理员巡检发出提醒；「看看原因」正确识别人为中断，事实、推断和建议分开回复。排查前后的 Git HEAD 与网页哈希一致，证明本次诊断没有修改文件。「接着做」回调在 1 毫秒内返回，正式流程恢复并完成修改。主动停止只用来验证运营恢复；Bug 修复由上述真实网页问题验证。

管理员实际修改了程序员角色说明和现有前端技能，完整测试通过后文字类提交生效，后续开发任务读取新规则。再发「撤销」，生成 Git revert，文件与修改前一致，无需重启团队。

代码类验收将工作台修复、临时技能文件和程序员技能绑定一起提交。签字前线上 HEAD 保持不变，签字回调 10 毫秒返回；完整测试后合并，团队进程 PID 改变、3 个机器人重新连接，工作台接口正常。新技能出现在工作台角色说明中，并由真实 `runAgent` 调用了 `Skill: team:acceptance-boundary`；它只读检查网页副本，报告证据及浏览器验证限制，文件哈希未变。临时技能仅用于验收，不加入发行版。

随后通过「撤销这次改动」按钮回退代码，确认 Git 内容恢复、团队进程再次重启、接口恢复且没有待签字变更。测试入口退出后恢复正式管理服务，只保留一套机器人连接。

最终由管理员按明确的验收指令确认项目，项目进入已完成。网页文件另用同一上传、发送接口复核，飞书返回 `code: 0` 和文件消息回执。未申请读取全群消息的额外权限，文件发送结果以接口回执为准。

## 能力边界

「看看原因」只查不改；恢复、确认、打回仍走正式阶段表。代码改动先签字，再执行测试和上线；有项目忙时延后重启。角色说明和已有技能属于文字改动，完整测试通过后直接生效。新增技能与角色绑定一起提交时，按代码类处理。

模型密钥、部署文件、编排核心、管理员自身代码不在管家的可修改范围内。管家没有命令行工具。运行机器的本地改动不会自动推送 GitHub，仍需编程助手审阅、测试和同步。

## 结论与复验

2026-11-26，本轮范围内验收通过：真实网页完成三轮走查和两次打回，26 项浏览器交互检查通过；管理员运营恢复、调度修复、文字改动与撤销、代码签字上线与撤销、新增 Skill 注册与真实调用均已验证。发行版离线测试 `npm test` 共 179 项通过，`npm run smoke` 的语法、工作台启动、首次安装三项通过。

这不是对任意未来模型输出的质量保证。AI 走查是读源码，曾漏掉实际手机输入框高度问题，因此仍需独立浏览器回归和截图复核。本轮没有故意让真实服务在错误代码上线后崩溃；自动回退分支由回归测试覆盖，本轮实际执行的是主动撤销后的恢复。
