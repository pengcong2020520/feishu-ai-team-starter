## 对抗检查发现的修复

- 群内真人尚未分配项目职责时，原实现连讨论也拒绝。现在启用的群成员可以讨论，正式操作仍按成员和关口权限校验。
- 最终验收后工作台已完成、工作区状态仍为待验收。现在阶段切换与启动时同步工作区状态，含升级前遗留快照的修复。
- 青杉在截止前打开取消弹窗、截止后确认仍能取消。通过正式打回，由程序员在实际取消时重新检查截止时间。
- 星河合法空列表重载被默认任务覆盖、存储文本被当作 HTML，以及第一次修复引入的可选字段误校验。均通过原 workflow 打回、修改和重新走查，最终浏览器回归通过。

Codex 完成上述对抗检查与复验。本轮 Grok CLI 额外只读辅助审查超过 15 分钟未返回结论，已停止，未记为通过；之前的独立审查另见[公开复现回测](公开复现回测.md)，不用于冒充新改动的审查。

## 覆盖边界与复跑

真实飞书群各有三位 AI 同事和一位真人。多人权限已做自动化，但未验证多位真人各自登录、平台签发回调、客户端点卡的完整联调。旧机器人消息是 `app` 身份，只能验证过滤，不能替代真人。

本轮复用了既有应用，未重新验证新租户扫码创建与审批；不同模型生成的文字与样式可能不同，必须按产物和浏览器行为验收。两个网页仍是单文件、本地数据演示，并非新增了后端。

发布新增启航版/领航版选择后，基础模式用正式装配和工作台请求验证不另建飞书群、不要求名册；领航模式用同一入口验证独立群和职责。缺少模式配置的既有独立项目保持领航版，不允许直接降级绕过权限。这部分自动化替换了外部传输和模型，没有声称重新扫码实测。

```sh
npm ci --no-audit --no-fund
npm test
npm run smoke
```

真实复现按[版本导航](版本导航.md)选择提示词。只有服务器、安装、真实消息、模型文件与浏览器分别有证据时，才报告对应层级通过。
