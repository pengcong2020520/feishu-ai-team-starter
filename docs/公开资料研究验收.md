# 公开资料研究工具与中国神华实测

日期：2026-11-28。中国神华独立项目已完成本机真实流程验收。真实项目编号、飞书群和文档编号、工具账本保存在本机，不随团队包导出。

## 交付范围

- 观澜 2.1.0，继续使用五个角色和原 workflow；与本机原 2.0 项目的 workflow 逐项比较一致。
- WebSearch 未配置 Brave 密钥时使用免费 Bing RSS；WebFetch 提供公开 HTTPS 网页和文字型 PDF 阅读；Calculate 提供有限数字运算。
- PDF 通过 Poppler 按物理页提取，支持关键词定位；单次读取至多 20 页，文件上限 25 MB，临时文件用后清理。macOS 安装 `brew install poppler`，Ubuntu 安装 `poppler-utils`；容器构建已声明该系统依赖。本轮只验收本机，未部署容器。
- 计算只执行列明的增长率、比率、加减乘除、幂、收益/回撤、DCF 运算，不执行模型生成的脚本。数字、公式、来源与结果保存在本项目的宿主证据账本。
- 已完成的旧群中，向协调机器人发“新研究：中国神华……”或“请你帮我研究一下中国神华”，生成开工提议；原发起人确认后新建独立群与工作区，不复制旧项目讨论。

## 实测方法

从旧项目的正式消息入口提出需求，经原开工确认接口创建真实飞书群，使用真实 Agent SDK、模型、Skill、搜索、PDF、计算和飞书文档接口。测试确认明确标为 Coding Agent 自动回测，不冒称真人审阅，不代表投资认可。没有使用飞书客户端前台操作。

研究初始主题为中国神华 A 股 601088 的 2025 年报与 2026 半年报：经营质量、现金流、分红及并购重述。用户随后在真实飞书群追加三季报与评级；首稿遗漏了这条较新的真人意见，验收打回后扩展范围并补做。测试需求提供官方 PDF URL，因此本轮不能证明搜索能独立找到所有财报。免费搜索确有返回无关结果，模型需要读取官方来源并明确缺口。

原计划七项任务：公司速览、宏观展望、财务口径表现比较、风险评估、情景分析、反方审查、综合研究报告。前面三项并行，后续按原依赖执行；不伪造股价序列和回撤。

## 实测中修复的问题

1. **旧群开工的本机身份无法确认**：本机身份使用可信 localPersonId，飞书入站身份继续通过通讯录绑定查找；不接受请求体伪造确认人。保留同一发起人确认与过期卡校验。
2. **只检索和计算、还没写报告就耗尽轮数**：研究工具任务单次 SDK 上限由 30 调至 60，普通任务仍 30、聊天仍 6；增加证据复用、及时落盘和失败检索收敛要求。原超时、并发上限和 workflow 均保留。重试仅执行未完成任务。
3. **长报告转换超过单次 1000 块**：按完整段落与表格子树分批写入，持久化转换结果、批次进度和幂等号。中断恢复复用原批次，全部成功才标记同步完成；单棵超大子树在写入前报错，不悄悄截断。
4. **旧自动确认被误称为最新用户意见**：派活提示改为带时间、来源的历史目标和关口记录，明确关口不等于群里最新发言，不得倒置时间或称真人撤回要求。本次使用原验收打回入口补入较新的真人需求，未改变 workflow。
5. **外部网页的畸形重定向可能终止服务**：将缺失、非法 Location 的解析错误收敛为工具失败；重定向仍逐次检查公网 HTTPS 地址，测试确认不发出内网请求。
6. **规划阶段提前做研究**：原规划调用也拿到了写文件和研究工具，导致选任务时重复计算。现在规划只可读项目资料、加载技能并提交结构化计划，正式任务才拿检索、计算、写入权限；原任务表、依赖关系和确认关口不变。

## 对抗审查与验证

- 检查项目目录隔离、来源账本哈希、工具真实调用、成功 Skill 回执、有限计算重放、审批来源及 workflow 是否改变。
- 检查 PDF 页码、重述前后、CAS/IFRS、全年/半年、当期分红/实际支付股息等口径。
- 已发现并回流一条推断错误：半年 FCF 对跨时点两笔股息的覆盖不足，不能直接推出全年缺口；H2 FCF 持平只是假设，需要计算并标明。另要求标题级宏观线索不能升级为已证实因果结论。
- 首稿还将“分别改变派息率、资本开支”的两个结果拼成“同时改变”的结果，组合覆盖率应约 1.172 而非 1.26，已随验收打回要求真实重算。
- 第二轮终稿仍把已宣派股息写成全部实付，且混用 FCF/股息与 OCF/总现金需求的公式；通过原验收关口再打回，仅修订综合稿。资产负债表增量不能直接认定为经营现金流的一次性贡献；跨税项与少数股东口径的加回计算也不能称为严格可比利润增速。
- 技术回归：260 项通过，包含真实小型 PDF 提取、非法计算拒绝、恶意重定向、角色工具边界、旧群开工权限、长文分批与丢失回执恢复。`git diff --check` 通过。
- Grok CLI 两次未产出审查结论，已终止；本次不声称获得 Grok 复核通过。

## 最终记录

- 旧群提出新研究 → 确认开工 → 独立飞书群与工作区 → 研究范围确认 → 并行专家研究 → 风险、情景与反方审查 → 综合报告 → 两次打回修改 → 自动回测验收，最终状态 `done`。五个角色均有真实 SDK 执行记录，原 workflow 与旧版逐项比较一致。
- 本次实际调用并成功加载 8 项 Skill：full-analysis、company-snapshot、macro-outlook、performance-comparison、risk-assessment、scenario-analysis、thesis-review、earnings-review。不是对团队包全部 16 项技能的全量验收；未触发 DCF、行情技术分析等任务。
- 宿主证据账本 600 条，缓存哈希全部核对；487 条计算记录重放一致（含尝试、复核与修订，并非 487 种独立算法）。9 份产物引用的 sourceId 均在账本中。SDK 记录未发现读取其他项目或演示输入的行为，权限边界另有离线回归。
- 9 份原生飞书文档均已共享到项目群、同步为“项目已完成”，真实接口回读最新标题与结尾通过，当前文件与持久化同步哈希一致，没有未完成批次或同步错误。旧版本为保留评论而追加留档，**最新修订版在文档末尾**；阶段稿中的旧推断以最终报告为准。
- 最后终审另直接修正了最终报告两处“65% 应由末期单笔满足”的表述：检查对象应为全年中期与末期现金分红合计。修改差异与自动回测审查说明均保留，不冒称 Agent 原稿无错或真人已审阅。
- 当前正式研究流程和最终文档已实测；新增规划只读边界由工具权限回归验证。全部 260 项测试通过。服务已加载最新修复并恢复运行。

结论是免费工具接入、旧群入口和原 workflow 的本机真实闭环通过，不是对模型所有财务判断的专业背书。两次打回证明本地计算正确仍不能替代口径和推断审查。

## 能力边界

没有新增付费数据订阅；模型接口仍按用户套餐计费。免费搜索不保证相关性、完整性或稳定性；扫描件 OCR、实时行情、专业历史行情库、自动回测引擎未接入。确定性计算只能证明算术正确，不能证明输入真实或推断成立。原始阶段稿可能保留研究分歧，应结合反方审查和最终报告阅读。
