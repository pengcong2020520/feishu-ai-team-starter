# 自己动手：搭一个飞书 AI 团队和工作台

目标：飞书群里有 3 个 AI 同事（AI 产品经理、AI 设计、AI 程序员），你 @ 它们提需求、点卡片确认，它们按"澄清 → PRD → 线框与主题 → 开发 → 走查 → 验收"把一个网页做出来；另有一个网页工作台，一屏看清所有项目和每个同事在做什么。

不用自己写代码：先下载起步包，再把提示词按顺序交给你的 AI 编程助手（Codex 或 Claude Code），一段做完、验收过了，再给下一段。

这套是启蒙版，跑通以后可以往很多方向拓展，见文末"拓展"。照着做一遍要多久、做出来什么样、踩过哪些坑，见[实测复盘](实测复盘.md)。

## 准备

| 要什么 | 说明 |
|---|---|
| 飞书 | 建议用自己创建的飞书团队：你是管理员，建应用、发布版本都不用等别人审批 |
| 电脑 | 装好 Node.js 24、git 和一个 AI 编程助手（Codex 或 Claude Code） |
| 模型密钥 | Agent 的"大脑"。用 Anthropic 的 API 密钥；也可以用兼容 Claude 接口的国内模型，例如火山方舟（`https://ark.cn-beijing.volces.com/api/compatible`）、DeepSeek（`https://api.deepseek.com/anthropic`） |
| 服务器（第 8 步才要） | 一台装了 Docker 的 Linux 服务器，能用 SSH 密钥登录 |

密钥只放在项目里的 `.env` 文件（权限 600），不要贴进聊天、代码或截图。

## 路线

| 步骤 | 做什么 | 做完的样子 |
|---|---|---|
| 0 | 下载起步包 | 目录里有项目说明书、施工图、角色说明和 8 个技能；AI 编程助手能说清要搭什么 |
| 1 | 建 3 个飞书机器人 | `.env` 里有 3 组 App ID 和 App Secret |
| 2 | 接入自检 | 在群里 @ 哪个机器人，哪个就回一张带按钮的卡片 |
| 3 | 第一个 Agent | 一个脚本让 AI 产品经理在文件夹里提问或写出 PRD，边跑边看到它用了哪些技能、读写了哪些文件 |
| 4 | 三个角色各跑一次 | 同一个文件夹里，设计画出线框和主题，程序员写出网页 |
| 5 | 编排 | 用假飞书、假智能体，测试里把完整流程和每个打回分支走通 |
| 6 | 串起来跑一遍 | 在真群里 @AI 产品经理，一路点卡片，拿到网页和走查页 |
| 7 | 工作台 | 浏览器打开 `http://127.0.0.1:4870/`，看到看板、项目详情和角色聊天 |
| 8 | 部署到服务器 | 服务器上一直在线，用 SSH 隧道打开工作台 |

### 第 0 步：下载起步包

新建一个空目录，在里面运行：

```
git clone https://github.com/pengcong2020520/feishu-ai-team-starter.git .
```

起步包里有：

- `AGENTS.md`：项目说明书，写清要做什么、整体结构、接口和文件格式、飞书卡片的写法、实测踩过的坑。Codex 每次开工会自动读它；`CLAUDE.md` 只有一行 `@AGENTS.md`，让 Claude Code 也读同一份。这样每一步的 AI 编程助手都带着同样的背景，不会各做各的。
- `prompts/`：4 份角色说明；`team-skills/`：8 个技能。澄清、PRD、需求自查、需求覆盖检查改编自 GitHub 的 spec-kit，线框、主题、走查、前端改编自一套设计工作流。它们是 Agent 的"提示词"，照原文用；跑起来以后可以按自己的需要改。
- `docs/施工图.md`（图版 `施工图.png`）：施工图。每一层有哪些模块、每个模块放在哪个文件、负责什么、通过什么接口相连、在第几步建出来。AI 编程助手照图施工，你照图验收。
- `docs/动手搭建.md`：就是这份路线。

然后在这个目录里打开 AI 编程助手，把提示词 0 给它，确认它读懂了。

### 第 1 步：建 3 个飞书机器人（二选一）

每个机器人最后要拿到两样东西：**App ID** 和 **App Secret**。

**方式 A：扫码一键创建（推荐）**。飞书官方 Node SDK 提供 `registerApp`：运行后出一个二维码，用飞书 App 扫码确认，应用就自动建好，权限、事件、回调都按预先声明的填好。把提示词 1 交给 AI 编程助手即可。

**方式 B：在开放平台手动创建**。每个机器人做一遍：

1. 打开 [飞书开放平台](https://open.feishu.cn/app) → 创建企业自建应用，名称写角色名（如"AI 产品经理"）。
2. 应用能力 → 添加"机器人"。
3. 权限管理 → 搜索权限代码并开通：
   - `im:message`
   - `im:message:send_as_bot`
   - `im:message.group_at_msg:readonly`
   - `im:chat:readonly`
   - `im:resource`

   不要开"获取群组中所有消息"：开了以后，机器人会收到别的机器人的回复，可能互相回复停不下来。
4. 事件与回调：
   - 订阅方式选"使用长连接接收事件/回调"；
   - 添加事件 `im.message.receive_v1`（接收消息）；
   - 添加回调 `card.action.trigger`（卡片回传交互）。

   长连接的意思是由你的程序主动连上飞书，所以不需要公网服务器，自己电脑上也能跑。如果保存时提示没有检测到连接，先完成第 2 步的自检，在程序运行时再回来保存。
5. 凭证与基础信息 → 复制 App ID 和 App Secret，写进 `.env`。
6. 版本管理与发布 → 创建版本 → 发布。

### 第 2 步：拉进群，做一次接入自检

在飞书里建一个群，把 3 个机器人都加进去，然后用提示词 2。三个都通了再往下走。

### 第 3–7 步：搭 AI 团队和工作台

开始第 3 步之前，先自己把模型的地址、密钥和模型名写进 `.env`（变量名见 `.env.example`），不要贴进聊天。然后依次使用提示词 3 到 7。

四个经验：

- 要一直运行的程序（第 2 步的自检、第 6 步以后的整套服务），让 AI 编程助手告诉你启动命令，你在自己的终端窗口里运行。它自己启动的程序，常常会随着它这一轮对话结束被关掉。
- 智能体干一次活要一到几分钟（实测：写 PRD 约 2 分半，线框与主题约 5 分钟，写网页约 7 分钟，走查约 6 分钟；一个需求从提出到验收，AI 一共干 20 多分钟）。看到进度在动就耐心等，不要中途停。
- 在群里只点最新的那张卡片；点"打回"后，按提示 @ 对应的角色说要改什么。
- 卡住了，把报错原样贴回给 AI 编程助手，让它查原因、修好、再验证。说不清哪里不对时，告诉它群里发生了什么，让它看消息记录、项目状态和服务日志。

### 第 8 步（可选）：部署到服务器

想让它不依赖自己的电脑一直在线，用提示词 8 部署到一台装了 Docker 的服务器上。因为用的是长连接，服务器不用开放任何公网端口。

## 提示词 1：扫码创建 3 个飞书机器人

```text
按 AGENTS.md 的约定，建 3 个飞书机器人：AI 产品经理、AI 设计、AI 程序员。写一个脚本 register.mjs 并运行它：
```

## 提示词 2：接入自检

```text
用 .env 里 3 个机器人的凭证写 listen.mjs，验证飞书接入（AGENTS.md 第 7 节）：
1. 每个机器人一条长连接，注册 im.message.receive_v1 和 card.action.trigger。
2. 按第 7 节过滤：只处理人发的、群里 @ 了自己的消息，同一条只处理一次，去掉 @ 占位符。
3. 收到后回一张卡片：标题是角色名，正文复述收到的文字，带一个按钮；点按钮后回调返回 toast"收到点击"。
4. 日志写进 listen.log：只记角色、事件类型和消息文字，不记凭证；30 分钟后自动退出。
写好后先自己启动一次，确认 3 条长连接都连上了，然后停掉，把启动命令告诉我：我在自己的终端里运行，在群里分别 @ 它们、点卡片按钮，再请你看日志告诉我哪个通了、哪个没通、可能的原因。
```

## 提示词 5：编排

```text
按 AGENTS.md 第 5、6、7 节写编排（src/flow/），这一步先不接真飞书：
```

## 提示词 6：串起来跑一遍

```text
把飞书接入、编排和 Agent 串起来（AGENTS.md 第 7、8 节）：

2. 进度卡片：中文标题写谁在做哪一步（如"AI 产品经理 · 澄清需求"），随 onProgress 实时显示读写的文件（相对路径；每 2 秒最多更新一次，15 秒没动静显示"正在思考……"），结束时显示用时和"读入 X / 写出 Y token"。

然后把启动命令告诉我：我在自己的终端里运行，在群里 @AI 产品经理提一个需求，一路点卡片；之后请你看日志帮我判断每一步是否正常。
```

## 提示词 7：工作台

```text
加一个网页工作台，和飞书群用同一套数据（AGENTS.md 第 8 节）：
1. 消息记录：把飞书和工作台的消息、卡片（包括更新后的版本）、按钮点击都记到 data/messages/<群>.jsonl；卡片转成网页能显示的结构：标题、文字、链接、按钮、问题表单。
2. 接口挂在 4870 端口：GET /api/state（所有项目的阶段、5 个步骤的状态、谁在干活、正在读写哪个文件、在等人做什么、已有的产物，以及 3 个角色的状态）；某个项目的消息、某个角色的消息、PRD 原文、某个角色的角色说明与技能原文；GET /api/events 用 SSE 推"有变化"。写接口：提新需求、给某个角色发消息、点卡片按钮，按第 8 节的安全要求做。
3. 前端（web/index.html、app.css、app.js，不用框架），长相照第 8.2 节：
   - 看板：按阶段分 6 列，项目卡片显示项目名、谁在干活、正在读写哪个文件、等你多久和 5 段进度条；底部是 3 个同事的状态；右上角"+ 提需求"；
   - 项目详情：左边是流程，中间按标签页看 PRD、线框、网页、走查页，右边是消息和卡片（按钮能点）和输入框；
   - 角色聊天：左边是同事列表，右边是对话和输入框，"角色说明与技能"浮窗看原文。
4. 写一个试用脚本：用假飞书和假智能体准备几个停在不同阶段的项目，在另一个端口启动工作台，方便我在浏览器里看。
如果服务正在运行，不要停它；改完告诉我怎么重启。
```

## 提示词 8：部署到服务器

```text
把当前的飞书 AI 团队部署到我的服务器（Ubuntu，已装 Docker，我能用 SSH 密钥登录 root@<服务器地址>）：
1. 写 Dockerfile（node:24-bookworm-slim，npm ci 安装依赖；Agent SDK 会自动装上 Linux 版的程序；一览图截图要装 chromium 和中文字体 fonts-wqy-microhei，CHROME_PATH 指向它，容器里的 Chromium 要加 --no-sandbox）和 compose.yaml：restart: unless-stopped，init: true，内存上限 1.5 GB，把 .env、data/、workspace/ 挂进容器。
2. 容器里的预览服务监听 0.0.0.0，端口只发布到服务器的 127.0.0.1（4870 工作台与走查页，4871 模型写的页面），不开放公网端口。
3. 用 rsync 把代码同步到服务器的 /opt/feishu-team（不传 node_modules、data、workspace 和日志），单独用 scp 传 .env，并把它的属主改成容器里的运行用户、权限 600。
4. 在服务器上构建并启动；启动前先停掉我电脑上正在运行的同一组机器人，同一组机器人不能两边同时在线。
5. 启动后看日志，确认 3 个机器人都已连上飞书，并检查容器里能连通模型接口（只列模型，不生成内容）。
6. 告诉我用 SSH 隧道打开工作台的命令：ssh -N -L 4870:127.0.0.1:4870 -L 4871:127.0.0.1:4871 root@<服务器地址>，然后在浏览器打开 http://127.0.0.1:4870/。
不要在任何输出里打印密钥。以后更新：先确认没有智能体在干活，再同步代码、重新构建。
```

## 拓展 A：加一个角色

```text
在当前的飞书 AI 团队里加一个角色"AI 测试"：
```
