# 开放团队包搭建提示词

把下面这段连同本仓库链接交给 Coding Agent：

> 请读取 AGENTS.md、docs/版本导航.md 和 docs/AI团队包规范.md。先确认我要的是原来的网页团队，还是可安装他人团队包的协作环境；已明确的选择不要重复问。保留既有项目与工作区；团队包的独立群使用包内的角色与工作流。
>
> 按 node setup.mjs 的下一步把本机服务跑通，不自行写扫码或建群脚本。已有机器人按标准命令增补权限。然后执行 node scripts/team-pack.mjs init，安装筑页、观澜和文枢三支团队。说明观澜 2.1 来自 TradingAgents 固定提交，五角色十六技能，保留 Apache-2.0。默认免费 Bing RSS 搜索、公开 HTTPS 网页阅读；检查 pdftotext 是否可用，缺少时协助安装 Poppler 后验证 PDF 读取。Calculate 是本地确定性运算，不是实时行情服务；实际研究优先官方来源并核对时期与口径，演示数据只用于明确标记的演示。验收须核对 context/source-ledger.jsonl 中的实际 search/read_pdf/calculate 记录，不能把工具声明当作成功。旧已完成项目群 @ 协调同事提新研究，确认开工后应新建独立群，旧上下文不迁入，workflow 不变。说明 Newtype 是固定上游版本的独立来源适配包，许可保留，不将其标为 MIT。
>
> 打开工作台首页，选择团队，核对角色、Skill 和完整 workflow。观澜创建自己的 5 个新角色，文枢创建自己的 8 个新角色，不复用产品经理冒充负责人或代建群。点“扫码连接飞书”，或运行 node scripts/team-pack.mjs bots <包ID> 打开同一扫码流程。先告诉我要弹二维码，由我在手机确认；当前团队已扫好的角色只复用，不重复创建。扫码后自动连接，Skill 按包加载，再新建飞书项目。新项目默认最新版本，旧项目不迁移。
>
> 不再要求设置人员名册或职责标签。扫码身份作为该团队工作台的操作者，私聊开工由提需求的人确认；新项目默认由发起人处理关口。用两种团队的独立项目验证上下文、会话、文件和确认卡隔离；验证必做任务、顺序与允许的并行。不要改变作者的协作规则。检查项目“来源与确认记录”，抓取来源必须有真实工具记录；自动确认要标明是回测，不推断真人已审阅。验证代码和模型交付分开记录，不把替身测试说成真实飞书。
>
> 若我要导入他人包，使用团队包工具校验并安装固定提交链接或导出文件；若我要分享自己的团队，使用 skills/team-packager/SKILL.md，保留原规则、许可和来源，实际完成导出与干净目录重新安装，默认不上传 GitHub。

> 飞书项目还要验证文档链路：协调机器人需要 docx:document 和 docs:permission.member:create（新团队扫码自动申请，已有团队补权并发布）。检查任务草稿与阶段交付进入原生飞书文档、项目群可访问、卡片有入口；添加明确标注测试的评论，确认只进入本项目上下文且不会自动批准或打回。正文按版本追加，人工编辑不会回写本地文件；结束项目的评论不自动重开流程。详见 docs/飞书文档同步与反馈.md。

> 如需标准团队包，先询问采用人工确认（推荐）还是独立自动审核；已明确选择时直接执行 `node setup.mjs review human` 或 `node setup.mjs review auto`。遵循 docs/命名与审核模式.md，明确额外审核节点、成本和失败停下规则。原始网页引擎仍保留四个人工关口，自动审核网页项目通过「筑页」团队包创建。新群名用“团队简称 · 简短主题”；项目表单可指定主题。验证跳转按钮带 ↗ 且不推进流程，操作按钮有明确执行含义。旧群、旧项目和锁定专业 Skill 不自动迁移。

> 验证群聊协调：已有项目群直接提出问题，无需每次 @；协调者按本项目角色分派。再提出修改，必须先看到补充/修改确认卡，“好的”不推进流程，非负责人不能代确认。明确 @ 优先，引用只取本群原文，附件不能假称已读。旧机器人需要 im:message.group_msg 权限并发布后才收得到普通消息。遵循 docs/群聊协调与上下文交接.md，保持原 workflow 和专业 Skill 契约。
