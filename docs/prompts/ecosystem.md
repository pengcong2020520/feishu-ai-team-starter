# 开放团队包 · 搭建提示词

适合使用观澜投研、文枢内容或他人分享的团队。工作台一次聚焦一支团队；切换团队不改变旧项目的角色和流程。无需同时创建所有团队的机器人。

把本仓库链接和下面整段交给 Coding Agent：

```text
我要搭建飞书 AI 团队的开放团队包版本，使用 main 完整代码，不从头重写。
先读 AGENTS.md、docs/版本导航.md、docs/部署与常驻.md、docs/工作台与成品复现.md 和 docs/AI团队包规范.md。
确认我要使用的团队：筑页（网页）、观澜（投研）、文枢（内容）或我提供的团队包；已明确的选择不重复问。
先选本地或服务器，再配置模型和机器人。本地执行 node setup.mjs deploy local；服务器收集 SSH 主机、账号、端口、登录方式和目录，按部署文档在远端执行标准 setup。
检查 Node.js >=24、Git、网络；模型必须支持 Anthropic 兼容消息、工具调用和结构化输出。密钥按 AGENTS.md 保存，不放到命令行、日志或 Git。
运行 node setup.mjs，按“下一步”完成基础服务。原有配置和机器人复用，只保留一处连接；不要自写扫码或建群脚本。
按 docs/工作台与成品复现.md 安装选定团队，不必一次安装三套。想浏览全目录时可用 node scripts/team-pack.mjs init。
询问人工确认还是独立自动审核，执行 node setup.mjs review human 或 review auto；已有明确选择直接沿用。保持包内 workflow 和专业 Skill 契约。
运行 node scripts/team-pack.mjs bots <包ID>，或点工作台“扫码连接飞书”。提前告诉我要弹出二维码，由我在手机确认。
观澜使用自己的5位角色，文枢使用自己的8位角色；不能拿产品经理冒充其协调者。当前团队已创建的身份只复用。
等待真实连接完成，在数字生命身份舱核对名称、职责和能力；进入工作台时检查斜向镜头转场和头像落位、跳过、减少动态效果，日常刷新不重播。
打开 setup 输出的工作台地址：首屏看当前团队的项目看板，底部3/5/8位角色可横滑，悬停看状态，点击进入提示词、Skill和历史任务；不显示人员职责管理。
用 docs/工作台与成品复现.md 的真实需求跑一遍。主题简短，飞书群名采用“团队简称 · 项目主题”，确认开工后由本团队协调者创建独立群。
验证飞书与工作台双向对话、连续补充、排队回复；普通聊天和文档评论不能冒充流程批准。原机器人缺少 im:message.group_msg 时只补权并发布。
协调机器人需要 docx:document、docs:permission.member:create、docs:document.media:upload。按 docs/图文安装与权限指南.md 检查实际权限、群成员访问、图文成果和评论回流。
最终 Markdown 应是一份可直接阅读的成品。检查独立质量检查及有问题时由原角色修正；不能把待办、占位或过程总结当作最终正文，也不能为通过检查编造来源。
文档内容不变时同步不得重复正文；内容变更应产生独立的新文档版本，保留旧版及人工编辑，工作台和卡片打开最新版本。
进入“项目档案”，核对AI摘要、标签筛选、最终成果、最初想法、生命周期节点及对应原始讨论；未完成项目保持真实阶段，不能为展示改成已完成。
验证第二个独立项目不串会话、文件和讨论，全服务并发默认上限3。记录实际模型/飞书结果与离线测试结果，缺少账号或权限时说明未覆盖项，不虚构通过。
需要定制团队时，按 docs/管理员助手.md 在管理员私聊里复制已安装包或导入 .team.json/固定提交链接；修改 Agent、Skill、workflow、workspace 草稿后，用真实任务试跑。说明试跑会使用模型额度，人工关口为测试模拟。检查最终产物与实际 Skill 回执，用户要求应用时才发布新版本，已有项目保持锁定。可直接在私聊导出和接收团队包文件；新团队应用后通过标准扫码连接自己的角色。
结束时给我工作台地址、项目及最新飞书文档链接、版本提交号和必要的日常命令。
```

## 团队特有准备

- **观澜 2.1**：适配 TradingAgents 固定提交，五角色十六技能，保留 Apache-2.0。默认用免费 Bing RSS 和公开 HTTPS 来源；先检查 `pdftotext`，缺少时安装 Poppler。真实研究核对 `context/source-ledger.jsonl` 中的搜索、PDF 和计算记录。Calculate 是本地运算，不提供实时行情或付费数据。
- **文枢**：安装器下载固定 Newtype 提交，保留 SUL-1.0 声明；网络失败需恢复安装，不能创建空包冒充成功。文章与归档说明是不同交付物，最终入口应指向文章正文。
- **第三方团队**：用 `team-pack.mjs install` 安装 `.team.json`、本地目录或固定 40 位提交的 GitHub 包目录链接。需要分享时使用 [team-packager Skill](../../skills/team-packager/SKILL.md)，完成校验、导出和干净目录重新安装，再按用户要求发布。
