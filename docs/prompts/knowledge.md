# Wiki 知识与连续记忆 · 搭建提示词

接在[启航版](basic.md)、[领航版](projects.md)或[开放团队包](ecosystem.md)之后使用。沿用用户已选择的团队、群模式和运行机器，不必额外安装文枢或创建机器人。

把仓库链接与下面整段交给 Coding Agent：

```text
请在现有飞书 AI 团队上配置 Wiki 知识与连续记忆，使用 main 完整代码。
先读 AGENTS.md、docs/Wiki知识层.md 和 docs/AI团队包规范.md，检查当前版本、配置与服务状态。
新安装先按已选版本的提示词完成标准 setup、管理员机器人和团队连接；已有安装保留 .env、data/、workspace/、.claude-agent-config/ 和管理员会话，不覆盖用户本地修改。有正在运行的任务时先等它完成，再更新并重启服务。
沿用原群模式、角色、专业 Skill 和 workflow；无需额外数据库、Embedding 服务或飞书知识库权限。
先确认哪些材料适合团队共享、哪些仅属于某个项目、哪些是管理员个人偏好。用户未提供材料时，用明确标注的测试草稿演示，不把演示内容写入正式项目。
团队知识只在个人草稿中编辑：让管理员从现有团队复制草稿，添加带标题、摘要、来源、状态和链接的知识页。已有团队包没有 knowledge 字段也可以继续使用；新增后由平台校验，禁止直接修改 data/packages 的锁定文件。
项目知识必须指定工作台实际项目编号；项目协作记忆同样明确项目。未指定项目的个人协作记忆只在管理员私聊使用，不传给群角色。
按本文的四组私聊示例验证新增、700→900修订、旧版查询及个人偏好接续。通过真人飞书消息入口发送，工作台“管理员调试”核对真实入站记录、回复和草稿差异；若只能以机器人身份发信，请用户发示例，不伪造真人入站，不要求飞书持续前台。
用两个新建测试项目验证项目隔离：只给A存一个测试约定，A的角色能查到，B的角色不能把它当成自己的事实。两个项目可读取各自包版本声明的团队公共知识；不要复制整个私聊或旧项目原文到公共知识。
在后续对话里自然追问前面的约定，核对最新值、旧值和来源。管理员继续同一 SDK 会话；长上下文整理前保留可检索原文，不能用清空会话或只留最近几轮来降低 token。
查看每轮输入、缓存读取、缓存写入和输出；上限触发时另核对整理记录。整理本身消耗模型额度，不能把累计会话用量当作本次消耗，也不保证每次都有固定节省比例。
按问题组织回复：先结论，简单问题简答，复杂比较再使用列表或表格；不要机械套模板。专业交付仍遵守各自 Skill 规范。
先运行 npm test 和 npm run smoke。若已安装文枢且模型已配置，可说明消耗后运行 node scripts/verify-knowledge.mjs --live；它是隔离的 SDK 测试，不是飞书真人私聊，也不会应用团队草稿。
需要正式使用团队知识时，在私聊中按用户的真实任务试跑草稿，检查角色确实检索了知识。试跑完成并获得用户明确的应用指令后，应用当前通过版本；新项目使用新版，旧项目继续原版本。需要分享时导出 .team.json 并验证重新导入，项目知识和个人记忆不自动打包。
结束时提供工作台地址、管理员调试入口、实际运行版本、知识页或草稿的查询方式，以及每项验证的实际结果。明确区分真人私聊、SDK调用、离线测试与尚未完成的项目验证。
```

## 四组私聊示例

把“文枢”替换为你实际安装的团队。项目编号使用工作台显示的真实编号，以下 A/B 仅表示两个测试项目。

**1. 团队知识：新增和修订**

> 从文枢复制一个个人草稿，叫“Wiki 入门测试”。新增团队知识“读者约定”：面向小店经营者，文章不超过700字，来源为我这条消息。保存后查询给我看，暂不应用。

收到回复后再发：

> 把刚才草稿的字数上限改成900字，其他不变。保留旧版，告诉我原来和现在分别是多少，来源是什么。暂不应用。

应能查到当前900字和历史700字；工作台“管理员调试”可以查看这两条真实指令及修改差异。草稿尚未应用时，正式团队的知识仍保持原样。

**2. 项目知识：只属于这个项目**

> 给测试项目 #实际编号 保存项目知识“交付时间”：周四16:30交稿，来源为我这条安排。这只是项目记录，不推进工作流。保存后查给我看。

在 A 群询问截止时间，再在 B 群问相同问题。B 应只依据自己的项目资料作答；没有约定时明确未知。不要用真实业务项目存虚构测试事实。

**3. 协作记忆：项目约定与个人偏好**

> 给测试项目 #实际编号 保存协作记忆：每次补充来源时说明发布日期和出处。仅此项目使用。

> 记住我的个人回复偏好：先说结论，简单问题简短回答。只用于管理员私聊，不放进团队包。

项目角色能查到所属项目的协作约定，但不会获得管理员个人偏好。

**4. 连续追问与分享**

> 刚才的个人回复偏好是什么？“Wiki 入门测试”的当前字数和以前字数分别是多少？请给出依据。

需要发布这个团队时，继续私聊说明试跑任务。查看结果后明确说“请应用 Wiki 入门测试的当前版本”；随后可说“导出这个团队包供分享”。应用要求当前版本的真实试跑记录，导出仅包含声明的团队文件。

## 已有安装怎么升级

在原安装目录检查 `git status` 和正在执行的任务，保存本地改动。代码更新后重启原服务，保留原管理员机器人和会话目录。Wiki 不需要再次扫码，也没有额外启用开关；新增个人记忆可以立即使用，团队知识按草稿版本发布。

团队包用于分享公共知识；整机迁移还需另外保留 `.env`、`data/`、`workspace/` 和 `.claude-agent-config/`，这些不上传公开仓库。项目知识按真实工作区路径隔离，迁移到不同绝对路径时需要单独迁移映射，不能仅导入团队包就声称旧记忆已经恢复。

实际机制与字段见 [Wiki 知识层](../Wiki知识层.md)，已有验证记录见 [本地验证报告](../reviews/wiki-knowledge-local.md)。
