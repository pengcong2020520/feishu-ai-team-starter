# 启航版 · 单群入门

适合先体验三个 AI 同事怎样把需求做成网页。3 位 AI 同事在原群协作，另有管理员助手和网页工作台。无需独立项目群、人员名册或职责配置。群内一个项目完成后可以继续提下一个；工作台保留历次项目产物。

## 给 coding agent 的搭建提示词

```text
我要搭建飞书 AI 团队「启航版 · 单群入门」。选择已经明确，不必再问版本。
从 https://github.com/pengcong2020520/feishu-ai-team-starter 的 main 安装完整代码。
先读 AGENTS.md、docs/版本导航.md、本文和 docs/复现指南.md，不重写项目。
检查 Node.js >=24、Git、联网条件，在新目录运行 node setup.mjs mode basic，再运行 node setup.mjs，按“下一步”完成。
模型用支持 Anthropic 消息、工具调用和结构化输出的接口；密钥只保存在 .env，不放进命令行、日志或提交。
如果已有机器人，复用现有凭证；先确认旧实例停下，跳过已完成的扫码，不重建应用。
应有产品经理、设计、程序员、管理员助手共4个机器人。首次缺少的机器人由 setup 出二维码，我在手机完成确认。
不要运行 upgrade-projects，不要求我导入人员或配置职责，不自动创建独立项目群。
完成后核对当前版本是启航版、四个连接、工作台及预览地址；确认工作台不显示“人员与职责”。
让我在原「AI 团队」群 @AI 产品经理提需求，先聊、点开工提议才执行；原 workflow 不变。
用 docs/复现指南.md 的单项目示例做浏览器验收，问题通过正式打回修复。
报告实际执行的命令、结果与未覆盖项。需要模型费用的真实任务先说明；没有我授权的验收代点不要替我确认。
```

## 验收与升级

确认在原群完成“澄清 → PRD → 设计 → 开发 → 走查 → 验收”，每关读产物，实际操作网页；私聊管理员发“状态”核对。启航版不校验“这个关口必须由某位同事确认”，需要此能力时使用领航版。

工作台提需求会优先使用空闲的已有群；该群有项目进行时，会另建仅在工作台中的本机会话。这是保留原行为，不会替用户新建飞书项目群。

后续升级不用重建机器人：按[领航版升级提示词](projects.md#已有启航版或旧机器人升级)增补原产品经理权限、重启和设置人员职责。升级前的旧项目沿用旧规则，之后的新项目才采用独立群和分工。
