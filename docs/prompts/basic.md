# 启航版 · 单群入门

适合先体验三个 AI 同事怎样把需求做成网页。3 位 AI 同事在原群协作，另有管理员助手和网页工作台。无需独立项目群、人员名册或职责配置。群内一个项目完成后可以继续提下一个；工作台保留历次项目产物。

> 安装前先按 docs/部署与常驻.md 确定部署位置，已明确选择不重复问。本地执行 `node setup.mjs deploy local` 后走标准 setup，验收系统自启和异常重启；服务器先收集 SSH 主机、用户名、端口、登录方式和目录，记录 `deploy server --host … --user …`，在远端执行 `deploy server --here` 和 setup。不要先在本机创建、运行机器人再决定部署。服务器首次扫码使用标准扫码页加 SSH 转发。说明 macOS 登录后自启、Linux 需要 linger，以及休眠/断网的边界；服务恢复只接续已在执行的步骤，不批准人工关口。

## 验收与升级

确认在原群完成“澄清 → PRD → 设计 → 开发 → 走查 → 验收”，每关读产物，实际操作网页；私聊管理员发“状态”核对。启航版不校验“这个关口必须由某位同事确认”，需要此能力时使用领航版。

工作台提需求会优先使用空闲的已有群；该群有项目进行时，会另建仅在工作台中的本机会话。这是保留原行为，不会替用户新建飞书项目群。

后续升级不用重建机器人：按[领航版升级提示词](projects.md#已有启航版或旧机器人升级)增补原产品经理权限、重启和验证发起人身份。升级前的旧项目沿用旧规则，之后的新项目才采用独立群和分工。

> 如需标准团队包，先询问采用人工确认（推荐）还是独立自动审核；已明确选择时直接执行 `node setup.mjs review human` 或 `node setup.mjs review auto`。遵循 docs/命名与审核模式.md，明确额外审核节点、成本和失败停下规则。原始网页引擎仍保留四个人工关口，自动审核网页项目通过「筑页」团队包创建。新群名用“团队简称 · 简短主题”；项目表单可指定主题。验证跳转按钮带 ↗ 且不推进流程，操作按钮有明确执行含义。旧群、旧项目和锁定专业 Skill 不自动迁移。

> 验证群聊协调：已有项目群直接提出问题，无需每次 @；协调者按本项目角色分派。再提出修改，必须先看到补充/修改确认卡，“好的”不推进流程，非负责人不能代确认。明确 @ 优先，引用只取本群原文，附件不能假称已读。旧机器人需要 im:message.group_msg 权限并发布后才收得到普通消息。遵循 docs/群聊协调与上下文交接.md，保持原 workflow 和专业 Skill 契约。

> 新建独立群前核对简短项目主题，优先采用用户明确的“项目名称/选题”，不要把整段需求当标题。群名统一为“团队简称 · 项目主题”，同名项目自动编号；重试创建保持原名称。
