# 领航版 · 多项目协作

适合多个项目同时做，且不同人员负责不同模块和确认事项。复用同一组三位 AI 同事，每项目一个群、一份工作区及每角色的 SDK 会话；管理员和工作台统一看进度，原 workflow 不变。

## 新安装提示词

```text
我要搭建飞书 AI 团队「领航版 · 多项目协作」。选择已经明确，不必再问版本。
使用 https://github.com/pengcong2020520/feishu-ai-team-starter 的 main 完整代码。
先读 AGENTS.md、docs/版本导航.md、本文与 docs/复现指南.md。
检查 Node.js >=24、Git、模型接口和网络，在新目录运行 node setup.mjs mode projects，再运行 node setup.mjs，按“下一步”继续。
新安装缺少的4个机器人由 node setup.mjs scan 创建；扫码由我在手机确认，密钥只保存在 .env。
先核对机器人和工作台连接，再带我打开“人员与职责”，从「AI 团队」或已有群导入真人，选自己并“设为本机操作者”。
每人可配多条岗位＋负责范围＋确认事项。按本文示例安排，不虚构飞书用户ID，不把机器人当真人。
设置好后用工作台建立两个不同范围的项目，默认“飞书新项目群”；核对两群、成员、确认人、独立工作区和会话。
在群里提需求时先给开工提议，点了才执行；工作台提需求直接开工，提前说明这一区别。
沿用原澄清→PRD→设计→开发→走查→验收，不能改阶段或跳过确认。
按下方清单验证并行、上下文和职责，实际浏览器操作产物，失败通过正式打回修复。
模型任务会花费用，先说明；按我的明确授权代点，否则由各关口指定人确认。保留命令和证据，区分真实、模拟与未覆盖。
```

## 已有启航版或旧机器人升级

```text
把当前安装升级为领航版，保留机器人、历史项目、.env、data/、workspace/ 和现有 SDK 会话目录。
先读 AGENTS.md 和 docs/复现指南.md。检查 git status，保留用户及管理员本地改动；从 main 正常合并更新，不 hard reset。
确认没有正在执行的步骤，备份后停服务。不能让同一组机器人在两台机器或两个目录同时连接。
运行 node setup.mjs upgrade-projects，给原 AI 产品经理扫码补权限；不要重新创建机器人。
授权成功会写入 TEAM_MODE=projects。运行 node setup.mjs 启动，检查版本、连接和实际接口权限。
在工作台导入真人、设置本机操作者、维护职责；不要手写安装完成标志或伪造人员身份。
旧项目按旧行为兼容。用两个新项目验证独立群、工作区和分工；记录未获批的权限和未入群人员，不把失败说成成功。
```

首次领航版扫码已申请全部群消息、私聊和拉人权限。已有应用缺权限时只更新原产品经理；具体是否生效以接口和实际入站事件为准。新账号扫码、租户审批可能需要该租户的管理员完成。

## 人员与职责示例

先把参与者加入产品经理所在的入口群，再从工作台“人员与职责”导入。以下名字只是示例，必须换成自己的真实成员，不要仅手填同名人代替身份。

| 人员 | 岗位 | 负责范围 | 确认事项 |
| --- | --- | --- | --- |
| 项目负责人（你） | 项目负责人 | APP、Agent 分两条职责填写 | 两个项目的最终验收 |
| APP 产品同事 | 产品 | APP | 需求澄清、需求确认 |
| APP 设计同事 | 设计 | APP | 设计确认 |
| Agent 模块同事 | 开发 | Agent | 需求澄清、需求确认、设计确认 |

新项目的“负责范围”填 `APP` 或 `Agent`。系统按范围文字匹配，不推断语义；一人多范围请添加多条职责。未匹配的关口交给负责人；同一关口匹配多人时，在新项目表单显式指定。也可明确选择成员和四个关口的确认人。

只有自己一人也能运行：导入自己并设置为本机操作者，添加 APP 与 Agent 两条职责，四关都由自己确认。此时能验证多项目和隔离，但不能据此宣布多人分权的真人联调通过。手工新增、没有飞书身份的人员仅用于本机项目；旧机器人只能验证 app 消息被过滤，不能冒充真人点卡。

## 两个可复制的需求

在工作台分别提交，创建位置都选“飞书新项目群”。不用照抄历史项目或真实个人数据。

**项目 A：青杉报名页；负责范围 `APP`。**

```text
做“青杉·周末徒步报名”单文件演示网页。固定30个名额，收姓名、手机号、紧急联系人、紧急电话。
活动日期用开始搭建后第14天的09:00，页面明确展示日期、集合点、路线和提醒。
活动前24小时截止取消；打开确认弹窗后如果跨过截止时刻，也不能取消。
验证必填、手机号、本人电话与紧急电话不同、重复报名和满额；取消需二次确认并释放名额。
刷新保留本机数据，存储失败时提示；手机无横向溢出。不需要后端、不共享其他设备数据。
```

**项目 B：星河监控页；负责范围 `Agent`。**

```text
做“星河·Agent任务监控”单文件只读演示网页。首次内置8条任务，覆盖排队中、执行中、成功、失败。
展示四态计数、任务名称、开始时间、耗时；多个任务可同时展开查看结果或错误。
每5秒自动刷新显示，手动刷新有加载态；不要开始、停止或重试任务的控制按钮。
localStorage保存任务，刷新不重置；合法空数组保持空状态，损坏数据可恢复。
存储里的名称、结果和错误均按纯文本显示；手机无横向溢出。不接真实任务后端。
```

## 复现验收清单

1. 两个群的群号、项目号、工作区不同，三位机器人复用；只邀请该项目分配的人员。部分邀请失败时显示未入群提示，处理审批或调整分工后补邀，不重复建群。
2. 在 A 群发不带 @ 的普通讨论，检查该项目“讨论”页及 `context/discussion.md`；内容不进入 B。同一条消息 @ 多位同事，依次产品、设计、程序员回复。
3. 分别让产品经理只读概括本项目需求：A 应讲 30 人报名，B 应讲 8 条只读任务。检查各角色只读取所属项目文件，会话按项目与角色分开；设计走查开新会话。
4. 两项目可同时设计、开发或走查。要观察 3 个名额和排队，可在两项正式任务运行时额外发只读问答；上限是整套服务的 `AGENT_CONCURRENCY`，默认 3，管理员也计入。
5. 让正确/错误的真人分别点卡：指定确认人可推进，其他人被拒绝，重复或跨项目旧卡不推进。群内未分工的启用人员可讨论；停用人员不能动作。没有多人账号时仅跑隔离自动化，并注明未真人联调。
6. 在非运行状态调整项目分工，旧确认卡失效，新卡发给新确认人；既有项目不随名册编辑自动改分工，移出分工不等于踢出群。
7. 实际浏览器测报名边界、截止竞态、刷新、空任务、纯文本显示、手机布局；问题走正式打回。最终工作台与 `context/project.json` 都为 `done`，各自飞书群收到网页文件。

自动化可运行 `npm test`、`npm run smoke`；聚焦本能力用 `node --test test/team-mode.test.mjs test/projects.test.mjs test/multi-person.test.mjs test/agents.test.mjs`。这些不调用真实模型、不替代新租户扫码和多人真人卡片回调。已完成的真实双项目验收及边界见[多项目验收](../多项目验收.md)。
