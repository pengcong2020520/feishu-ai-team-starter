## 对抗审查

1. **旧提示词抵触自动模式**：真实模型最初因缺少真人点击记录而拒绝已合格草稿。修复为明确的平台模式优先级，仅把非问答确认交给独立审核，不覆盖专业交付要求和对外发布权限。重试后实际通过，最初失败记录保留。
2. **并行部分成功绕过审核**：初版重试可能只审失败重做的任务，漏审同批已成功的产物。改为依据 completed 与 reviewed 的差集审核，测试证明成功上游也必须审核后才派发下游，且不重复生产。
3. **模型空口通过**：必须具备逐产物依据、实际 Read 成功事件、有效文件检查及未变化的内容摘要，否则停下；有 blocker 时即使 passed=true 也拒绝。
4. **过期或被修改的成果确认**：校验项目/阶段/卡号；人工确认前再次比对受检产物摘要，变化后发新卡并拒绝本次旧确认。重启不默认通过。
5. **权限与来源混淆**：人工确认仍走项目身份授权；附加关口由负责人处理，原关口保留指定确认人。自动来源明确记账，不伪造真人，不自动执行外部发布。
6. **恢复与停止**：等待审核的位置和已完成任务持久化；自动审核接入全局容量和停止控制。失败可重审，支持打回的关口可提交修改意见，未知分支不生成虚假按钮。

剩余限制：自动审核是文件规则和模型判断，不是事实真实性保证；复杂需求的规则短名可能仍需用户在创建表单改写。未迁移旧群名与历史卡片，未做跨设备截图走查。
