# 文档与飞书呈现补充规范

版本：1.0；日期：2026-11-28。适用于所有团队的文档交付。已有专业 Skill 的结构、字段、编号、篇幅、来源声明和校验优先；本规范只补缺。

## 1. 已有规范盘点

| 产物 | 规范来源 | 保留事项 |
|---|---|---|
| PRD | prd-spec | 九类章节、80 行限制、FR/SC 编号、用户故事与状态、来源声明、outline.json 一致性 |
| 线框与主题 | lofi-wireframe、theme-pick | HTML 状态导航、design-outline、theme.json 字段和设计令牌 |
| 开发与走查 | frontend-design、flow-walkthrough、consistency-check | 单文件网页、状态标识、走查 JSON、覆盖与问题字段 |
| 投研 | investment-lab 各专业 Skill | 问题与口径、时间、证据、分析、反证、缺口和来源；各技能既有方法 |
| 内容制作 | 当前锁定的 Newtype 角色与 Skill | 原写作、编辑、核查和归档分工；补充一般文章的读者结构，不替换其方法 |

JSON、HTML 不转成普通公文，不为排版改变机器可读字段。已安装包保持锁定，平台补充规则不修改包源文件。

## 2. 写作顺序

1. 定位：这是什么文档、给谁看、读完要理解或决定什么？
2. 识别专业规范：先读取本任务 Skill，列出必备内容和不可改字段。
3. 排大纲：每节写一个核心问题、应得出的结果、需要哪些依据，以及与下一节的关系。大纲在已有获准交付位置组织，不新增审批关口。
4. 填内容：从资料选择支持该节的内容；事实给出处，分析写推导，观点写条件，资料不足标明本次缺口。
5. 审稿：只看标题能否看出逻辑？正文是否回答标题？结论能否回溯证据？是否重复、缺项、超长或偷换口径？

不能先堆满材料再补几个标题；不为凑模板虚构内容，也不一律要求先写结论——文章可用场景起笔，决策报告应让读者尽早看到判断。

## 3. 缺少专业模板时的补充格式

| 类型 | 建议脉络 | 信息栏与标题 |
|---|---|---|
| 公众号观点文章 | 场景或问题 → 核心主张 → 分论点与证据 → 条件/反例 → 收束 | 标题自然、具体、有观点；一般不加管理信息栏、章节编号或验收日志 |
| 研究报告 | 研究问题与口径 → 主要判断 → 证据与分析 → 反证/风险 → 缺口/来源 | 类型、对象、资料截止日期、适用范围；标题为对象＋研究问题 |
| 方案说明 | 目标与范围 → 选择及依据 → 实施安排 → 验收与风险 | 适用范围、真实状态；有专业 Skill 时以其章节为准 |
| 操作说明 | 使用前提 → 按序操作 → 可观察结果 → 异常与恢复 | 适用版本或条件；标题说明要完成的任务 |
| 过程与归档记录 | 实际结果 → 依据 → 未解决事项 → 后续动作 | 真实日期、来源与状态；与成品分开，保留专业审计要求 |

研究报告可以细分为：1 研究问题（1.1 对象与范围、1.2 时间与口径）；2 主要判断；3 证据分析（3.1 支持证据、3.2 推导、3.3 反证）；4 风险与限制；5 来源。已有投研 Skill 规定业务、估值、财务等章节时，使用其专业结构，不用这个通用大纲替换。

文章示例：“产品即分发：AI 硬件正在争夺什么？”可作为候选标题，但不能为了朗朗上口承诺尚未证实的市场爆发。每篇最终标题仍须由写作任务结合实际正文拟定。

## 4. 飞书呈现

- 新文档名称优先取正文主标题；缺主标题才用产物名称。不拼接整段需求、角色职责和执行状态。
- 单份内容只设一个主标题，正文按二、三级标题组织。不把加粗段落伪装成结构标题，也不自动重排专业编号。
- 状态与更新时间用简短说明，正文不再额外套一层“角色职责＋状态”大标题。
- 专业 Skill 要求的 frontmatter 在本地保留；发布副本移除原始 YAML 外壳，只提取 tags/description 的安全标量为标签、说明。其他信息保留在本地，不能据字段名推断真人已审核。
- 表格承载同维比较，顺序列表表达步骤，普通列表表达并列事项。数字、日期、链接、限制、来源声明保持完整。
- 正文中的技术细节是否保留由文档用途决定：开发文档需要的代码不能删，文章不混入工具日志和编辑对照。
- 本轮保留原有末尾追加版本机制，以保护人工编辑和评论；新规范不自动重写历史文档、不删除旧版本。阅读入口仍需明确最新版本在末尾。

## 5. 执行边界与验收

正式任务统一注入补充写作要求；对话与结构化计划不套长文规范。同步只处理发布外观，不用正则重写正文论证，不删除专业章节。

测试须证明 PRD 章节/FR/SC、代码块、来源与正文未被变换；frontmatter 本地未改；标题不再来自长需求；发布不新增重复主标题。文章逻辑、标题吸引力与事实推导仍需要内容审稿，不能仅凭格式测试声称写作质量通过。

## 参考与取舍

- [Microsoft 写作指南](https://learn.microsoft.com/en-us/style-guide/scannable-content/)：短段落、清晰标题与适合浏览的结构。用于呈现，不替代专业内容。
- [GOV.UK 内容结构指南](https://guidance.publishing.service.gov.uk/writing-to-gov-uk-standards/writing-guidelines/clear-structure/)：描述性标题、重要信息前置、避免重复。本项目不照搬其禁止疑问标题等特定编辑规则。
- [Atlassian PRD 指南](https://www.atlassian.com/agile/product-management/requirements/)：目标、背景、需求等面向协作的内容组织；本项目 PRD 继续以现有 prd-spec 为准。
- [CFA 研究报告要素](https://www.cfainstitute.org/sites/default/files/-/media/documents/support/research-challenge/challenge/rc-equity-research-report-essentials.pdf)：研究判断、估值、风险与依据；不把竞赛格式或投资评级强制用于所有研究任务。

群名、项目主题、卡片标题和跳转按钮遵循[命名与审核模式](命名与审核模式.md)。原有专业文档格式仍优先；新增审核属于平台执行机制，不借机重写 PRD、设计、程序交付契约。原生飞书文档的标题与正文仍按本规范处理，文档评论不等于正式确认。
