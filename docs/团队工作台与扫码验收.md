## 对抗审查

1. 自定义团队是否借用产品经理建群：已修正为协调机器人；应用 open_id 不跨应用使用。真实飞书成员查询确认观澜五角色、文枢八角色分别在各自群内，两个群均没有原产品经理。
2. 重复点击、部分扫码成功、保存绑定中断是否创建重复应用：覆盖同任务复用、补绑定与失败重试。
3. 飞书一次建群最多邀请 5 个机器人：文枢首次请求被真实 API 拒绝（99992402，bot_id_list 最大长度 5）。已修复为先创建群并落盘，再分批补齐其余机器人；补齐前不启动工作流，失败重试复用同一群。新增八角色邀请失败回归。
4. 不同团队是否开出相同应用的第二条长连接：按应用 ID 拒绝重复连接，已有连接复用。
5. 新项目是否仍按旧职责拉入其他人：团队包创建默认仅发起人；历史项目仍校验原确认人。
6. 版本更新后旧项目是否读到新角色：项目的流程与角色说明均从内容摘要锁定包读取。
7. 界面刷新、切换项目是否串未发送内容：发现并修正草稿复用问题，按项目保存并用真实页面操作回归。
8. 是否将计划完成当成全部任务完成：实际计划与成功 Skill 留档；未选择任务不显示为完成，结束项目不伪报未执行节点。
9. 扫码接口是否允许跨站请求或读取任意文件：沿用同源、JSON、专用请求头和大小限制；二维码只暴露当前任务的白名单文件。
10. 阶段没变时飞书讨论是否仍刷新：发现原界面只随项目状态重画，已将讨论刷新独立出来，保留输入草稿，并验证普通消息不会推进工作流。
11. 文档是否还引导用户操作已删除的人员功能：清理 AGENTS、复现指南和领航版提示词中的旧导入/编辑步骤，保留历史权限的说明。
