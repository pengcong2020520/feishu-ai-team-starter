# 公开仓库复现回测

2026-11-26，从 GitHub `main` 的 `9a8bceb` 干净克隆开始，使用 Node 24、现有模型接口和四个机器人。未复制旧项目、旧模型会话或安装完成标志。按用户要求跳过重新扫码创建机器人；先停原实例，再启动新目录，避免同一机器人同时连接两处。

## 方法

Codex 执行安装、真实需求和浏览器交互；Grok CLI 独立读取公开仓库，实际运行离线回归和接口检查。Grok 的观察时点早于项目完成，不能把中途“尚无线框”当成最终失败，也不能把安装状态的勾选当成完整验收。

新需求是一个固定 3 个名额的读书会报名演示页，覆盖昵称校验、重复报名、满额、取消确认、刷新持久化、存储降级和手机布局。先用“暂时不要创建项目”验证只聊天，再用完整需求提议开工，确认后才进入阶段表。

输入和按钮通过正式工作台接口送入共享编排，下游使用真实模型、文件、截图和飞书发送接口。这不是飞书客户端收消息或真人点击的重测。没有使用桌面前台自动化。

## 真实发现与修复

| 发现 | 证据与处理 |
|---|---|
| 已确认开工后仍只回复开工提议 | 原版产品经理只调用了一次 Glob，没有写文件；文件检查拒绝交付。角色说明同时含聊天和派活规则，调用缺少明确模式。修复后由代码在系统提示尾部明确本次模式。 |
| 未交付文件却先显示“已完成” | 原版进度卡只看 SDK 正常结束，随后才检查文件。现在文件、字段和轮次检查通过后才能显示完成，失败时保持原阶段并显示没做完。 |
| 同一问题卡或停下卡同时提交会重复执行 | 并发提交回答、重试与结束均复现重复操作。问题文件读取后重新核对状态；停下、结束与插话卡在异步记录或更新前消费卡片。定向回归只执行一次，另一次判过期。 |
| 管理员引用否定句片段也能代点 | Grok 独立用“先不要确认，只改文案”等反例复现。现在只接受最新一条完整的明确短指令，动作、项目、关口必须匹配；多个待确认项目须指明编号。原话更新会撤销旧授权，每条指令只能代点一次，不能复用到下一关。 |
| 当前安装与历史从零教程混用 | Grok 独立确认 `learn` 只有较早的三个同事，没有当前管理员、后台服务与 Git 工作副本。README 和复现指南指向 `main` 完整版，历史教程明确范围并修正分支命令。 |
| 旧部署提示词与当前容器不一致 | 现行版本需要保留 Git 工作区、管理服务入口与容器用户权限；宿主端口默认 4880/4881。新增当前部署提示词，并提醒使用 setup 打印的实际地址。 |

没有把首次失败改写成通过：原版首次开工仍记失败，正式重试恢复另记结果。修复版在独立新会话重跑同一句需求，实际使用 PRD 与自查技能，写出 PRD、页面结构和自查清单，文件契约通过。

完整项目在公开基线运行。随后在同一测试副本应用本次两处代码补丁并重启，四个机器人重新连接，已完成项目保持 `done`。候选版另用信息不足的新提示词，真实调用澄清技能并交付合法问题文件；只读聊天正确解释跨手机不能共享本地名额，网页哈希与项目状态未变。候选补丁、原版全流程和浏览器结果分别留证，不把它们混称为同一版本从头跑到尾。

## 最终对抗审查

Grok CLI 独立审查了安装、阶段表、角色权限、管理员工具与工作副本、工作台隔离以及公开提示词。它复现了管理员截取原话即可代点的问题，也独立重跑了并发卡片失败；修复后再次运行 `npm test`，186/186 通过，原最小复现脚本 8 项通过且无遗留发现。最终复核还确认文字与按钮停止都会先撤销未使用的代点授权。

最终审查范围内没有剩余可复现问题。Grok 的浏览器结论来自核对主助手留下的结果与动作记录，它没有自行重做飞书客户端或浏览器操作；上述真实模型、Chrome 和飞书发送验证由 Codex 执行。审查不等于对所有未来输入作保证。

## 范围限制

本轮未重新扫码创建应用，也未验证另一个租户的管理员审批。历史 `learn` 路线未从零重写并验收当前四机器人系统；复现当前效果应使用 `main`。

管理员的真实运营恢复、文字修改与撤销、代码签字与撤销、Skill 注册及实际调用见[上一轮验收](管理员助手验收.md)。本轮累计离线回归包含这些代码分支，不把旧的真实运行记录冒充本轮重做。

模型生成不保证每次文字或网页样式一致。安装连通、文件契约、模型源码走查和实际浏览器交互是不同层次的证据，应分别验证。
