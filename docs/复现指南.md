# 用公开仓库复现当前团队

先看[版本导航](版本导航.md)：**启航版**用于单群入门，**领航版**用于多项目、多群、上下文隔离和分别确认；两套提示词分别保留在 [basic.md](prompts/basic.md) 和 [projects.md](prompts/projects.md)。两版都使用 `main` 的完整代码，都有三个 AI 同事、管理员助手和工作台。`learn` 是历史从零编程练习，不要与当前安装提示词混用。

复现指角色、流程、卡片和工作台行为一致；模型生成的文字、线框和网页样式不要求逐像素一致。请记录 `git rev-parse HEAD`、Node 版本和模型名，便于定位差异。

## 新用户：把这一段交给编程助手

```text
帮我运行 https://github.com/pengcong2020520/feishu-ai-team-starter 的 main 完整版本。
在新目录克隆，先读 AGENTS.md、README.md 和 docs/版本导航.md，检查 Node.js >=24 与 git。
我未选版本时，先问要启航版（单群入门）还是领航版（多项目协作），再读对应完整提示词；已明确就不用重复问。
不要重写已有程序。先运行 node setup.mjs mode basic 或 node setup.mjs mode projects 保存选择，再运行 node setup.mjs，按“下一步”继续。
模型凭证只保存在 .env，不展示密钥。先验证模型，再创建缺少的机器人。
应有 AI 产品经理、AI 设计、AI 程序员和 AI 管理员助手共4个机器人。
依赖和后台服务交给 setup 管理，扫码需要我在手机上完成时再提示我。
完成后核对选择的版本、四个连接、工作台和预览地址。
启航版直接在原群提需求；领航版通过可信扫码记录或真实私聊识别发起人，再建独立项目群。人员职责管理已删除，不要求导入名册。告诉我如何确认开工、回答问题和验收。
不能验证的项目请明确列出，不要把“已写文件”当作“能运行”。
```

模型必须提供 Anthropic 兼容的消息和工具调用能力。仅通过一次连通检查不足以证明能驱动 Agent；安装后还应跑一次真实需求。Chrome/Chromium 用于一览图；缺少它时流程可以继续，但卡片没有截图，不能视为完整视觉复现。

## 已有机器人：复用而不重建

```text
我已有四个机器人，请复用现有 .env 中的飞书凭证与管理员 OPEN_ID，跳过已完成的扫码。
先确认要保留的版本；已有独立项目继续使用领航版。没有多项目需要的旧单群安装继续启航版。
先确认同一组机器人原来的运行位置，并停止旧实例，再启动这里；不能只看当前目录的 npm run status 就断言没有其他实例。
克隆 main 的完整代码，运行 node setup.mjs。已有 data/setup.json 时保留真实安装进度；没有时让 setup 完成模型验证和建群，不要手填“已完成”标志。
原目录升级优先。保留历史项目时先停服务并备份 .env、data/、workspace/、.claude-agent-config/；跨机器或路径迁移要另验会话续用，不能只复制产物就宣称恢复完成。
只做干净回测时只迁移账号配置，不复制旧项目或模型会话；仍只能启动一处。
从启航版升级领航版时，按 docs/prompts/projects.md 给原产品经理增补权限，核对发起人身份，不重建机器人。
检查 .env 中的端口、Chrome路径和 PUBLIC_* 地址是否适合新机器，不要直接沿用另一台机器的路径。
```

只有机器人凭证而没有原安装记录时，安装脚本可能创建「AI 团队」群并给出入群链接。不同应用下的管理员 `open_id` 不能混用。

## 安装后：单项目流程验证（两版通用）

启航版在原群推进，领航版通过扫码或真实私聊识别发起人，确认开工后去新项目群推进。领航版双项目复现请继续用[两项目需求与验收清单](prompts/projects.md#两个可复制的需求)。

先在群里 @AI 产品经理说：

```text
先别开工。我想做一个周末读书会报名页，只在自己电脑演示，名额3人。
先告诉我单文件网页能做什么、不能做什么，暂时不要创建项目。
```

确认它只回复、没有擅自开项目，再说：

```text
请提议开工：做一个“周末读书会报名”单文件本地演示页。
固定3个名额，只收昵称，去首尾空格后1到20字，同名不能重复报名。
显示人数、剩余名额和名单，满额后阻止新增。取消报名需确认，取消后释放名额。
刷新保留数据，存储不可用时提示并允许当前页面继续操作；适配375px手机。
不用后端、不采手机号、不做跨设备共享。先发开工提议，等我确认。
```

按正式卡片依次回答澄清、确认 PRD、确认设计、验收。每一关先读产物。验收时实际测试空白、重名、满额、取消与刷新；再私聊管理员发“状态”，核对项目现状。不要仅凭模型说“通过”就完成验收。

也可以把以下提示词交给编程助手执行浏览器验收：

```text
请用独立后台 Chrome/Chromium 实际操作生成的网页，保留测试结果和手机截图。
覆盖昵称空白、20/21字边界、去空格、重名、回车提交、3人满额后拒绝第4人、原生取消确认与确认删除、刷新保留，以及HTML昵称按纯文本显示。
分别模拟localStorage读取失败、写入失败、读写都失败，三种情况都应提示并允许内存报名与取消；不要只验证一种异常。
在375px检查横向溢出、输入框和取消按钮；本轮验收约定触控高度至少40px。
逐个打开outline里的状态，确认演示状态不覆盖真实保存的数据。
发现失败时记录原结果，通过正式“打回”和修改意见让程序员修复，自动走查后再跑完整浏览器回归。不得直接改阶段或伪造通过记录。
```

## 部署当前版本

```text
请部署当前main完整版本，先读AGENTS.md的管理员与容器约定、Dockerfile和compose.yaml。
在服务器用git clone保留完整.git工作区，不用仅复制源码的方式代替；用SSH传输.env，不打印内容。
当前compose把整个仓库挂到/app，属主需与容器用户10001一致；.env权限600。依赖由镜像安装，不复制本机node_modules。
确认旧实例没有项目在干活，停止旧实例，再docker compose up -d --build；同一组机器人只连一处。
检查管理员与三个同事连接、工作台/api/state和预览地址。宿主只绑定127.0.0.1，不开放公网。
按实际compose端口建立SSH隧道（默认宿主4880/4881），不要套用历史文档中的4870/4871宿主端口。
更新前先查看git status和管理员变更记录，保留本地提交；上游与本地有分叉时正常合并，不hard reset，不覆盖data或workspace。
```

## 出问题时给助手的调试提示词

```text
请先列出这一步预期的输入、状态转换、输出文件和用户可见反馈，再用实际证据定位差异。
检查服务状态、data/service.log、工作台/api/state、消息与卡片记录；不打印密钥或完整HTTP请求对象。
先核对当前版本：启航版没有人员名册和独立项目群是正常行为；领航版核对可信发起人身份、确认关口和独立项目会话；团队包使用自己的角色机器人。
区分安装问题、飞书接入问题、模型问题、编排问题和网页交互问题。
先做最小复现，再修复根因；补跑失败项、累计回归和相关权限边界。
优先使用接口和独立后台浏览器，不要求飞书持续保持前台。
结果分别写“已执行通过”“执行失败”“未覆盖”，附命令或证据位置。
```

## 发给 Grok CLI 的最终对抗审查提示词

```text
假设“别人照README就能复现”这个结论是错的，请独立寻找反例。
只依据公开仓库、实际测试输出和允许访问的接口，不信任开发者的通过声明。
检查干净安装、4个机器人、模型工具调用、单实例、关口与重复按钮、权限、异常恢复、Git工作副本、Docker和端口、缺少Chrome、工作台交互与手机尺寸。
分别核验启航版和领航版：不能只改提示词而运行同一种行为；已有独立项目不能切基础模式绕过权限。
领航版额外找跨项目串内容、错人点卡、重复建群、部分邀请失败、旧卡重放、并发超限和上下文状态落后等反例。
每个发现给出文件位置、触发条件、最小复现、实际影响及证据；推断与已复现分开。
不能执行的项目标未覆盖，不要编造通过。不读密钥，不提交、不推送、不改线上状态。
```

`npm test` 和 `npm run smoke` 验证确定性的代码与启动行为；真实模型、真实飞书和实际网页仍需单独验证。扫码创建已按用户要求跳过的回测，不能证明新账号的扫码创建和租户审批已经通过。

实际跑过什么、发现了什么、哪些没有覆盖，见[公开复现回测](公开复现回测.md)、[管理员助手验收](管理员助手验收.md)和[多项目验收](多项目验收.md)。
