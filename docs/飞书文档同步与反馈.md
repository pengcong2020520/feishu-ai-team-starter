# 飞书文档同步与反馈

适用于标准团队包的飞书项目（观澜、文枢及其他包）；本机项目不调用飞书，旧 `src/flow` 项目暂未接入。

## 怎么使用

1. 每个团队由自己的协调机器人维护文档，不借用其他团队身份。新团队扫码时协调者申请 `docx:document`、`docs:permission.member:create` 和 `docs:document.media:upload`。已有机器人需在开放平台开通并发布，保留原应用。后者用于文档内配图，不是聊天图片的 `im:resource`；具体缺失项以真实 API 返回为准。
2. 工作流中声明为 Markdown 的产物自动同步：任务执行中每 30 秒检查本步输出，标记为“草稿 · 尚未通过交付检查”；文件交付检查通过后追加“阶段交付”版本；工作流完成时自动同步“项目已完成”版本。只有实际存在的文件才生成文档，JSON、网页、凭据和未声明文件不会上传。
3. 确认卡和完成卡提供文档入口，工作台项目详情列出全部文档。旧项目可以点“同步文档与评论”，或在群中 @ 同事说“同步文档”。同步不会重新执行已经完成的工作流。
4. 在飞书文档中添加全文或局部评论、回复评论。服务每 60 秒轮询，正式任务开始前也会拉取；群聊按需读取本地已同步版本，不等待逐份远端查询。意见写入当前项目的 `context/document-feedback.md` 和 JSON，Agent 按提示读取。运行中新增评论不会强行中断当前模型调用，下次调用读取。
5. 要求执行修改仍需按原流程打回并提交意见；评论里的“确认”“批准”不构成批准事件。已完成的项目不会因为新增评论自动重新开工。

## 内容与权限

- 每项目、每产物对应固定文档。内容变更时在同一文档末尾追加新版本，不清空正文、不覆盖人的编辑、不删除原评论。当前是单向发布产物＋评论反馈，人工直接改正文不会自动覆盖本地交付文件。
- 项目群获得编辑权限，不开放互联网公开编辑。文档由本团队协调机器人创建，机器人身份、项目映射与模型凭据分离。
- 反馈记录保留来源文档、评论号、作者身份、引用、回复、解决与移除状态。它们是外部参考资料，不能更改 Agent 权限或绕过确认人。
- 同步错误显示在工作台和后续卡片，不把成功的业务步骤改成失败；权限或网络恢复后可手动同步。重复同步不会追加相同内容和相同状态的版本。
- 单份 Markdown 限 200 KB；转换后按完整段落/表格子树分批写入，每批不超过 1000 块和 50 个一级块。批次内容、进度及幂等号先落盘，中断后续写，全部完成才标记已同步。单棵子树超过 1000 块时在写入前报错，不截断表格。批注附件识别、正文双向合并不在本次范围。

## 图文发布

配图只在有助于理解时使用，保留各专业 Skill 的章节与篇幅。支持两种来源：

- `team-figure` 围栏：有界 JSON 定义顺序流程或同口径非负数比较。平台使用固定 SVG 模板和本机 Chrome/Chromium 生成 PNG，不执行 Agent 的 HTML、SVG 或脚本。语法见[配图契约](../skills/illustrated-documents/references/figures.md)。
- 已有图片：标准 `![说明](assets/example.png)`，相对于该 Markdown，真实文件必须在同一项目内。支持 PNG、JPEG、WebP，最多 8 张、每张 8 MB。远程地址、绝对路径、越界软链接、伪装格式会报错；带标题的图片语法、引用式图片和 HTML 图片暂不支持。

正文先解释问题，图旁保留含义、来源和口径；数据必须核实。结构化配图自动附上图注和来源段落，已有图片的图注由作者写在相邻正文。没有可用素材时不要填写不存在的路径。指南示例见[图文文档示例](examples/图文文档示例.md)。

同步会冻结当次图片 → 官方 Markdown 转块 → 插入原生图片块 → 以真实块号上传素材 → 绑定 token → 回读确认。原文和图片任一变更都会产生新版本。图片出错时工作台保留失败原因，可能已有部分正文，不会虚报全部同步成功；重试使用保存的进度，不重复插入正文或重复上传已有回执的图片。素材上传超过 60 秒返回同步错误；如果上传回执完全丢失，重试可能产生未绑定的素材，但不新建重复正文。

旧图片、旧文档不会被自动重写。原网页引擎与本机项目不执行本链路。已有团队补权限后，使用工作台“同步文档与评论”验证；只有接口回读通过才报告图片绑定成功，仍需查看实际阅读效果。[飞书素材接口](https://open.feishu.cn/document/server-docs/docs/drive-v1/media/upload_all)

## 实现与恢复

- `src/feishu-documents.mjs`：SDK 创建、群协作者权限、官方 Markdown 转原生块、嵌套块插入、原生图片上传绑定与回读、评论及回复分页读取。表格剔除只读 `table.property.merge_info`。
- `src/document-visuals.mjs`：有界图形生成、图片类型与真实路径校验、版本快照。只准备发布副本，不改写源文档。
- `src/packages/documents.mjs`：项目级队列、正文与图片摘要、固定文档映射、追加请求幂等号、反馈隔离。映射持久化于 `data/project-documents/<项目号>.json`，图片版本在 `data/document-assets/<项目号>/`，需随项目状态一起备份，不属于团队包分享内容。不能在待续传时删除图片缓存。
- `src/packages/engine.mjs`：任务草稿/交付/完成同步、卡片链接、问答读取本地反馈；`src/main.mjs` 启停轮询；`POST /api/packages/documents` 使用同源保护和既有本机/管理员身份，校验讨论权限。
- 文档创建 API 没有幂等键：创建前持久化标记，收到编号立即保存。若进程在返回编号前中断，不自动重复建文档，须核查已创建文档后恢复编号。追加内容重试复用保存的请求号；续传旧草稿后，同一次同步继续发布当前文件和状态，不能把旧版本误当最新交付。
