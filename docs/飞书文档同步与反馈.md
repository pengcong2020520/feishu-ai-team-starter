# 飞书文档同步与反馈

适用于标准团队包的飞书项目（观澜、文枢及其他包）；本机项目不调用飞书，旧 `src/flow` 项目暂未接入。

## 怎么使用

1. 每个团队由自己的协调机器人维护文档，不借用其他团队身份。新团队扫码时协调者申请 `docx:document` 和 `docs:permission.member:create`。已有机器人需在开放平台开通并发布，保留原应用。
2. 工作流中声明为 Markdown 的产物自动同步：任务执行中每 30 秒检查本步输出，标记为“草稿 · 尚未通过交付检查”；文件交付检查通过后追加“阶段交付”版本；工作流完成时自动同步“项目已完成”版本。只有实际存在的文件才生成文档，JSON、网页、凭据和未声明文件不会上传。
3. 确认卡和完成卡提供文档入口，工作台项目详情列出全部文档。旧项目可以点“同步文档与评论”，或在群中 @ 同事说“同步文档”。同步不会重新执行已经完成的工作流。
4. 在飞书文档中添加全文或局部评论、回复评论。服务每 60 秒轮询，正式任务开始前也会拉取；群聊按需读取本地已同步版本，不等待逐份远端查询。意见写入当前项目的 `context/document-feedback.md` 和 JSON，Agent 按提示读取。运行中新增评论不会强行中断当前模型调用，下次调用读取。
5. 要求执行修改仍需按原流程打回并提交意见；评论里的“确认”“批准”不构成批准事件。已完成的项目不会因为新增评论自动重新开工。

## 内容与权限

- 每项目、每产物对应固定文档。内容变更时在同一文档末尾追加新版本，不清空正文、不覆盖人的编辑、不删除原评论。当前是单向发布产物＋评论反馈，人工直接改正文不会自动覆盖本地交付文件。
- 项目群获得编辑权限，不开放互联网公开编辑。文档由本团队协调机器人创建，机器人身份、项目映射与模型凭据分离。
- 反馈记录保留来源文档、评论号、作者身份、引用、回复、解决与移除状态。它们是外部参考资料，不能更改 Agent 权限或绕过确认人。
- 同步错误显示在工作台和后续卡片，不把成功的业务步骤改成失败；权限或网络恢复后可手动同步。重复同步不会追加相同内容和相同状态的版本。
- 单份 Markdown 限 200 KB；转换后按完整段落/表格子树分批写入，每批不超过 1000 块和 50 个一级块。批次内容、进度及幂等号先落盘，中断后续写，全部完成才标记已同步。单棵子树超过 1000 块时在写入前报错，不截断表格。图片素材上传、批注附件识别、正文双向合并不在本次范围。

## 实现与恢复

- `src/feishu-documents.mjs`：SDK 创建、群协作者权限、官方 Markdown 转原生块、嵌套块插入、评论及回复分页读取。表格剔除只读 `table.property.merge_info`。
- `src/packages/documents.mjs`：项目级队列、内容摘要、固定文档映射、追加请求幂等号、反馈隔离。映射持久化于 `data/project-documents/<项目号>.json`，需随项目状态一起备份，不属于团队包分享内容。
- `src/packages/engine.mjs`：任务草稿/交付/完成同步、卡片链接、问答读取本地反馈；`src/main.mjs` 启停轮询；`POST /api/packages/documents` 使用同源保护和既有本机/管理员身份，校验讨论权限。
- 文档创建 API 没有幂等键：创建前持久化标记，收到编号立即保存。若进程在返回编号前中断，不自动重复建文档，须核查已创建文档后恢复编号。追加内容重试复用保存的请求号；续传旧草稿后，同一次同步继续发布当前文件和状态，不能把旧版本误当最新交付。
