# 施工图：飞书 AI 团队（启蒙版）

管理服务带着团队服务，三个角色共用 Agent SDK 运行代码，按项目和角色隔离上下文；飞书走长连接，网页只开在本机。下图为多项目结构；原 [施工图.png](施工图.png) 为启蒙版历史图。约定细节以 [AGENTS.md](../AGENTS.md) 为准。

```
多个飞书项目群 ⇄ 接入层/完整讨论 ⇄ 原阶段编排 ⇄ 全局执行名额 ⇄ Agent SDK
                          ⇅          ⇅              ⇅          ⇅
                团队包/确认关口    本机工作台      管理员管家   各项目工作区
```

## 编排

`src/main.mjs` 通过 `src/team.mjs` 装配团队，`src/team-mode.mjs` 读取版本选择。启航版不装配项目管理，仍在原群逐个做项目；领航版装配下列多项目模块。两版共用 Agent SDK、管理员和 `src/flow/stages.mjs` 的澄清 → PRD → 设计 → 开发 → 走查 → 验收。没有配置字段的旧安装按既有独立项目判断模式，禁止已有独立项目目录降级绕过分工。

| 新模块 | 文件 | 负责与接口 |
|---|---|---|
| 身份目录 | `src/projects/directory.mjs` | 可信扫码和入站身份；历史项目权限兼容；新团队包默认由发起人确认；数据 `data/team.json` |
| 项目管理 | `src/projects/manager.mjs` | 当前团队协调机器人创建独立群和邀请成员；持久化幂等请求 `data/project-registry.json`；校验项目动作权限，群内真人讨论不要求承担项目职责；写 `context/discussion.md` / `project.json`，阶段切换和服务启动时同步状态 |
| 讨论入口 | `src/projects/events.mjs` | 全部真人消息留档，多个机器人去重；点名多个角色按序交给原对话队列；未点名消息仅一次送到团队包接续判断，按项目、真人和十分钟有效期路由聊天，其他消息只留档 |
| 全局容量 | `src/agents/capacity.mjs` | `AGENT_CONCURRENCY` 默认 3；管理员和团队跨进程共用，超额等待、不启动 SDK；排队可取消 |
| 工作台接口 | `src/preview.mjs` | `/` 团队页，`/legacy` 旧网页详情，`/api/context` 讨论；人员名册与编辑接口已删除 |

工作台聚焦单个当前团队，首页优先展示四列项目看板，底部横滑头像通过浮窗展示项目、阶段与当前活动；团队生态入口切换成熟包，角色详情展示 Skill、项目详情保留完整流程；已有机器人通过 `node setup.mjs upgrade-projects` 更新原产品经理权限。飞书建群成功后先保存群号，再邀请人员，失败重试不另建群。新群终身绑定一个项目，旧项目行为保留。

团队包群聊由 `src/packages/engine.mjs` 管理独立回复卡与逐群队列。最近讨论直接送入模型，按需读取本地文档评论；后台文档同步不阻塞聊天。排队最多五分钟，实际回答另计一分钟；失败回复与正式任务失败分开。已完成群的协调角色可把新研究、写作目标或聊天提议交给 `lobby.mjs` 发开工卡，确认后才创建独立项目，不改变已安装包的 workflow。

| 模块 | 文件 | 负责 | 第几步 |
|---|---|---|---|
| 阶段表 | `src/flow/stages.mjs` | 9 个阶段 + 3 个打回分支，每个阶段谁负责、"现在该谁做什么"，只能按表跳转 | 5 |
| 编排 | `src/flow/index.mjs` | 按阶段派活、发任务消息；同角色续用会话、走查开新会话；人只在 4 个关口出手，其余自动接着派；群里 @ 角色先聊，开工、修改要点提议卡；对正在干活的角色说的话先记下，可插进这一步（引导）或让它停下；出错就停（停下卡：重试 / 结束项目）；每步时间上限 | 5 |
| 群聊对话 | `src/flow/chat.mjs` | 被 @ 时角色回一句话；按项目现状和被 @ 的角色算出能提的动作（开工、修改、回答、重试、结束），校验模型的提议；提议发成卡片，人点了才由编排执行 | 5 |
| 给用户的提示 | `src/flow/guide.mjs` | 出错时的一句话原因、"现在该做什么"、过期卡片该怎么说、进度卡上的人话（这一步在做什么、现在在做什么） | 5 |
| 交付检查 | `src/flow/validate.mjs` | 按文件契约检查每一步的产物，不信智能体说"做完了" | 4、5 |
| 卡片 | `src/flow/cards.mjs` | 进度卡（1.0，patch 更新；一行人话说现在在做什么 + 停下按钮）、问题卡（2.0 表单）、确认/打回卡（1.0 按钮）、提议卡、排队卡（现在引导 / 停下这一步）、停下卡、结束确认卡、完成卡 | 5、6 |
| 走查页 | `src/walkthrough-page.mjs` | 读 `design/walkthrough.json`，用固定模板生成走查页：每屏嵌真实网页、标记、反馈、导出 | 6 |
| 一览图 | `src/sheet.mjs` | 把线框、网页、走查的各个状态排成一页（两列、最多 6 格），无头 Chrome 截成一张图，上传后放进卡片，下面配"打开线框"等链接；失败不卡流程 | 6 |
| 消息记录 | `src/workbench/recorder.mjs` | 飞书和工作台的消息、卡片、按钮点击记到 `data/messages/<群>.jsonl` | 7 |

编排 ⇄ 智能体层：`runAgent({ role, prompt, projectDir, resume, onProgress, timeoutMs, mode, control }) → { ok, text, structured?, sessionId, error?, stopped?, stats }`。`control` 由 runAgent 填上 `steer(text)`（以 `priority: 'now'` 插进这一步）和 `stop()`（`interrupt()`）。`mode: 'chat'` 是群聊对话：只读、开新会话，`structured` 是 `{ reply, proposal }`。

| 角色 | 角色说明 | 技能（插件 team） | 写什么 | 第几步 |

## 基础设施（本机文件）

管理员团队调试由 `src/admin/team-lab.mjs` 管理草稿与版本，`team-lab-tools.mjs` 提供私聊天然语言工具。`team-trial-worker.mjs` 在独立目录调用原团队包编排和共享 SDK，`team-lab-page.mjs` 提供只读过程/产物页与结果卡。私聊附件进入 `data/admin/team-imports/`；草稿、逐次试跑和分享文件位于 `data/admin/team-lab/`。只有应用操作将已通过的精确摘要安装到正式包目录，不改变原项目记录与会话。

运行期间的 `run.json` 由试跑进程单独写入，通知回执另存 `notice.json`；故障接续必须等待旧进程退出，并核对草稿摘要，沿原项目的失败节点继续。`src/packages/edit-lock.mjs` 为管理员应用和工作台提示词编辑提供同一份进程锁，保留持有者信息并回收已退出进程的锁；草稿编辑、试跑和应用另共用跨进程草稿锁。锁的持有者信息完整写好后原子发布。

| 东西 | 位置 | 说明 |
|---|---|---|
| 密钥与配置 | `.env`（600） | 3 组飞书凭证、模型地址/密钥/模型名 |
| 项目状态 | `data/state.json` | 每个群一个当前项目：阶段、项目号、各角色会话 id、等人点的卡片；每个群最新的一条提议 |
| 消息记录 | `data/messages/<群>.jsonl` | 工作台读它 |
| 工作区 | `workspace/<项目号>/docs · design · site` | 智能体只读写这里 |
| 项目讨论与分工 | `workspace/<项目号>/context/` | 编排写入，三位同事只读；普通讨论不替代关口确认 |
| 隔离会话目录 | `.claude-agent-config/isolated/<路径摘要>/<角色>/` | 新项目按项目＋角色存 SDK 会话；禁用自动记忆注入，原文不跨项目共享 |
| 人员与建项请求 | `data/team.json`、`data/project-registry.json` | 身份/职责、项目分工、建群重试信息 |
| 共享执行名额 | `data/agent-capacity/` | 当前进程的执行与排队记录，管理服务与团队服务共用 |
| 角色与技能 | `prompts/`、`team-skills/` | 起步包提供的原文 |

## 开放团队包结构

```text
包目录 / .team.json / GitHub 固定提交
  → 清单与路径校验 → data/packages/<包>/<版本>/<摘要>
  → 项目锁定 → 通用编排 task / gate / plan / done
                  ↓                    ↓
          角色提示词 + Skill       可信身份与人工确认
                  ↓
          原 runAgent + 全局并发名额
                  ↓
        独立项目 Workspace / SDK 会话
```

## 命名与阶段审核

参见 [命名与审核模式](命名与审核模式.md)。`src/project-labels.mjs` 管理项目短名与卡片标题；`src/packages/engine.mjs` 在原团队包依赖图外增加可选审核暂停，`src/agents/run.mjs` 的 review 模式提供隔离只读审核。安装命令 `node setup.mjs review human|auto` 只影响新团队包项目，旧项目和原始网页引擎不自动改方式。

## 群聊协调与受控交接

`events.mjs` 保留 parent/root 消息引用和附件元数据；`packages/group-routing.mjs` 定义只读路由契约；`packages/engine.mjs` 的 groupMessage 管理逐群队列、分派回执与独立补充确认；`projects/coordinator.mjs` 为原网页引擎接入相同的路由判断。确认补充写入项目 context/confirmed-inputs.json，当前任务经 control.steer 接收；已有成果修改回到原 reject 入口。路由判断、普通讨论与审批记录严格区分。

工作台显示态：`engine.mjs` 仅在内存维护 `liveActivities`，对外提供群聊回复、协调分派与独立审核的执行/排队状态，结束即移除，不写入项目状态或改变阶段。正式任务沿用 `activities` 与 `running`；旧网页项目沿用 `activeRole`、`queuedForAgent`。浏览器每三秒刷新，角色可关联多个项目；默认回到上次选择的团队。

## 工作台 V2 数据补充

- `src/workbench/history.mjs`：按项目过滤完整消息文件，以文件位置分页；卡片更新回填原卡片位置，不冒充新对话。`/api/messages?paginated=1` 支持向前游标及已加载卡片更新，旧接口行为保留。
- `src/packages/prompt-editor.mjs`：团队级保存锁、当前版本校验、复制到临时包、只修改目标角色提示词及清单版本、标准校验安装；旧项目继续用原摘要。`POST /api/packages/prompt` 沿用同源与管理员令牌约束。
- `engine.mjs`：成功记录补充任务名与输出引用，失败尝试放独立 `attempts`；产物补充文件更新时间、标题与作者关联。它们只用于展示，不替换 workflow 的成功标记或阶段表。
- `web/teams.*`：头像浮窗与横滑、提示词编辑、Skill 目录、历史任务、项目聊天及产物阅读窗；输入草稿与阅读位置按项目保留。

### 紧凑工作台与身份关联

- `directory.mjs` 的 `samePerson` / `equivalentPeople` 关联扫码和群聊产生的同人记录，保留历史人员编号；同应用 open_id 才可比较。
- `manager.mjs` 在服务端识别系统管理员；管理员可处理任意项目当前操作，其他成员仍按原确认人执行。`context/discussion.md` 单列管理员最新明确意见，不把聊天变成批准。
- `POST /api/packages/name` 调用 `engine.renameProject`、`manager.renameProject` 和 `feishu.renameChat`；同步项目/群/工作区名称，保留原工作流和历史名。
- 工作台消息通过飞书发送后只记一条用户记录，保存回执 ID；管理员助手使用的 `/api/message` 同样处理。飞书入站继续按消息 ID 去重，前端由 SSE 和轮询更新。
- 四列看板采用紧凑项目卡，底部职业头像点击直达角色页；交付物时间线显示文稿、作者头像和外链。操作按钮、文稿入口、历史动作分开呈现。
