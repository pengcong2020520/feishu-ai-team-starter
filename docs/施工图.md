# 施工图：飞书 AI 团队（启蒙版）

一个 Node 进程 + 3 个 Agent（Agent SDK）；飞书走长连接，网页只开在本机。动手前先对照这张图：每个模块放在哪个文件、负责什么、和谁通过什么接口相连、在第几步建出来。图版见 [施工图.png](施工图.png)。约定细节以 [AGENTS.md](../AGENTS.md) 为准。

```
飞书群 ⇄ 接入层 ⇄ 编排 ⇄ 智能体层（Agent SDK）⇄ 工作区文件
              ⇅                  ⇅
     预览服务与工作台（本机）      模型接口
```

## 安装层（开箱即用时由 setup 完成；从零搭的路线对应第 1–2 步）

| 模块 | 文件 | 负责 | 接口 |
|---|---|---|---|
| 入口 | `setup.mjs`、`src/setup/run.mjs` | 判断搭到哪一步，做下一件事，打印给 AI 助手的"下一步"；服务停过时把它拉起来，列出没做完的项目，`resume` 替用户发"重试" | `node setup.mjs [scan\|status\|resume <编号>\|model …\|--use-anthropic-env]`；工作台 `GET /api/state`、`POST /api/message` |
| 配置 | `src/setup/env-file.mjs`、`progress.mjs` | `.env` 更新式读写（600）；进度写 `data/setup.json` | — |
| 模型检查 | `src/setup/model.mjs` | 沿用终端 `ANTHROPIC_*`；发一次极短请求检查连通 | `POST <MODEL_BASE_URL>/v1/messages` |
| 装依赖 | `src/setup/install.mjs` | 后台 `npm ci`，官方源连不上换 npmmirror | `data/install.json`、`data/install.log` |
| 扫码 | `src/setup/register.mjs` | 3 张码并行、断网重试、过期换码、建成即写入 | SDK `registerApp`（`createOnly`、`addons`） |
| 建群 | `src/setup/group.mjs` | 产品经理建「AI 团队」、用户当群主（不行就给群分享链接）、拉另外两个机器人、报到卡片 | `im.v1.chat.create`、`im.v1.chat.link`、`im.v1.message.create` |
| 服务管理 | `src/setup/service.mjs`、`scripts/service.mjs` | 后台常驻启动、停止、查看；端口被占自动换 | `npm start / stop / status`、`data/service.pid`、`.env` 的 `PREVIEW_PORT` |

## 接入层

| 模块 | 文件 | 负责 | 接口 | 第几步 |
|---|---|---|---|---|
| 飞书 · 3 个机器人 | `src/feishu.mjs` | 每个机器人一条长连接；过滤（人发的、@ 了自己、message_id 去重、去掉 @ 占位符）；发消息、发卡片、更新卡片、传图片和文件；失败时带上飞书的 code 和 msg | 事件 `im.message.receive_v1`、回调 `card.action.trigger`；`im.v1.message.create / patch`、`im.v1.image.create`、`im.v1.file.create` | 1、2、6 |
| 预览服务 | `src/preview.mjs` | 两个端口、不同源：模型写的页面和代码生成的页面分开；CSP、nosniff、no-store | `:4871 /p/<项目号>/wireframe`、`/site`；`:4870 /p/<项目号>/walkthrough` | 6 |
| 工作台接口 | `src/preview.mjs`（或 `src/workbench/`） | 读：项目、消息、PRD、角色原文；写：提需求、给角色发消息、点卡片按钮，调用编排里和飞书同一套处理函数 | `GET /api/state`、`GET /api/events`（SSE）；`POST` 写接口要 `X-Workbench: 1`、同源、JSON ≤ 16 KB | 7 |
| 工作台前端 | `web/` | 看板（6 列）、项目详情（流程 · 产物标签页 · 消息与卡片）、角色聊天、提需求 | 只调上面的接口；模型写的文字用 `textContent`，模型写的页面放 sandbox iframe | 7 |

接入层 ⇄ 编排：`onMessage({ chatId, role, text, user })`、`onCardAction({ chatId, value, formValue, user })`；编排通过接入层发卡片、更新卡片。

## 编排

| 模块 | 文件 | 负责 | 第几步 |
|---|---|---|---|
| 阶段表 | `src/flow/stages.mjs` | 9 个阶段 + 3 个打回分支，每个阶段谁负责、"现在该谁做什么"，只能按表跳转 | 5 |
| 编排 | `src/flow/index.mjs` | 按阶段派活、发任务消息；同角色续用会话、走查开新会话；人只在 4 个关口出手，其余自动接着派；群里 @ 角色先聊，开工、修改要点提议卡；对正在干活的角色说的话先记下，可插进这一步（引导）或让它停下；出错就停（停下卡：重试 / 结束项目）；每步时间上限 | 5 |
| 群聊对话 | `src/flow/chat.mjs` | 被 @ 时角色回一句话；按项目现状和被 @ 的角色算出能提的动作（开工、修改、回答、重试、结束），校验模型的提议；提议发成卡片，人点了才由编排执行 | 5 |
| 给用户的提示 | `src/flow/guide.mjs` | 出错时的一句话原因、"现在该做什么"、过期卡片该怎么说、进度卡上的人话（这一步在做什么、现在在做什么） | 5 |
| 交付检查 | `src/flow/validate.mjs` | 按文件契约检查每一步的产物，不信智能体说"做完了" | 4、5 |
| 卡片 | `src/flow/cards.mjs` | 进度卡（1.0，patch 更新；一行人话说现在在做什么 + 停下按钮）、问题卡（2.0 表单）、确认/打回卡（1.0 按钮）、提议卡、排队卡（现在引导 / 停下这一步）、停下卡、结束确认卡、完成卡 | 5、6 |
| 走查页 | `src/walkthrough-page.mjs` | 读 `design/walkthrough.json`，用固定模板生成走查页：每屏嵌真实网页、标记、反馈、导出 | 6 |
| 一览图 | `src/sheet.mjs` | 把线框、网页、走查的各个状态排成一页（两列、最多 6 格），无头 Chrome 截成一张图，上传后放进卡片，下面配"打开线框"等链接；失败不卡流程 | 6 |
| 消息记录 | `src/workbench/recorder.mjs` | 飞书和工作台的消息、卡片、按钮点击记到 `data/messages/<群>.jsonl` | 7 |

编排 ⇄ 智能体层：`runAgent({ role, prompt, projectDir, resume, onProgress, timeoutMs, mode, control }) → { ok, text, structured?, sessionId, error?, stopped?, stats }`。`control` 由 runAgent 填上 `steer(text)`（以 `priority: 'now'` 插进这一步）和 `stop()`（`interrupt()`）。`mode: 'chat'` 是群聊对话：只读、开新会话，`structured` 是 `{ reply, proposal }`。

## 智能体层（`src/agents/run.mjs` → Agent SDK `query()` → Claude Code 子进程）

| 角色 | 角色说明 | 技能（插件 team） | 写什么 | 第几步 |
|---|---|---|---|---|
| AI 产品经理 `product` | `prompts/product.md` | clarify · prd-spec · spec-checklist | `docs/questions.json`、`prd.md`、`outline.json`、`checklist.md` | 3 |
| AI 设计 `designer` | `prompts/designer.md` | lofi-wireframe · theme-pick · flow-walkthrough · consistency-check | `design/wireframe.html`、`theme.json`、`walkthrough.json` | 4 |
| AI 程序员 `developer` | `prompts/developer.md` | frontend-design | `site/index.html` | 4 |

三个角色共用：`prompts/shared.md`；工具 Read、Write、Edit、Glob、Skill（没有命令行）；`canUseTool` 只准写本角色的目录；env 白名单（拿不到飞书密钥）；`maxTurns: 30`；`onProgress` 实时报告工具调用。群聊对话时只给 Read、Glob，不用技能，`maxTurns: 6`，按固定格式返回回复和提议。角色表在 `src/agents/roles.mjs`。

## 基础设施（本机文件）

| 东西 | 位置 | 说明 |
|---|---|---|
| 密钥与配置 | `.env`（600） | 3 组飞书凭证、模型地址/密钥/模型名 |
| 项目状态 | `data/state.json` | 每个群一个当前项目：阶段、项目号、各角色会话 id、等人点的卡片；每个群最新的一条提议 |
| 消息记录 | `data/messages/<群>.jsonl` | 工作台读它 |
| 工作区 | `workspace/<项目号>/docs · design · site` | 智能体只读写这里 |
| 角色与技能 | `prompts/`、`team-skills/` | 起步包提供的原文 |
