# 开源投研适配与内容团队补充

本轮日期：2026-11-27。网页团队未改动。观澜从自定义六角色升级为 **TradingAgents 五角色、十六技能**；文枢继续使用 Newtype 八角色，补充可核对的来源与确认记录。

## 投研来源与适配范围

上游为 [TauricResearch/TradingAgents](https://github.com/TauricResearch/TradingAgents/tree/121265d18d467ac717f7af99cb0d669c15d2e73c)，固定提交 `121265d18d467ac717f7af99cb0d669c15d2e73c`，发布提交为 1.0.1，许可 Apache-2.0。本平台包版本为 `investment-lab@2.0.1`。固定提交中的实际实现为主研究 Agent 加四个专家，不沿用搜索引擎缓存里的旧版角色介绍。

| 角色 | 标准 Skill |
| --- | --- |
| AI 研究主理人 | full-analysis、scenario-analysis |
| AI 公司研究员 | company-snapshot、filing-review、earnings-preview、earnings-review、dcf-valuation、relative-valuation |
| AI 宏观策略师 | macro-outlook、market-brief、sector-review |
| AI 量化研究员 | performance-comparison、technical-analysis |
| AI 风险分析师 | risk-assessment、portfolio-review、thesis-review |

原始四专家提示词、主研究提示词和十六个 Skill 保留在包内 `upstream/`；修改后的角色与 Skill、协作规则、声明式任务目录、工作区模板及交付文件使用现有 `feishu-team/1` 协议。许可及差异见包内 `LICENSE`、`THIRD_PARTY_NOTICES.md` 和 `examples/author-mapping.md`。

工作流：明确范围 → 确认范围 → 主理人选择任务 → 专家研究 → 风险/反方与情景 → 综合报告 → 验收。公司、宏观和量化可并行；同角色串行；汇总必须等待所有选中任务。按问题选择 Skill，不要求每次机械运行全部十六项。失败重试保留已经完成的任务。

数据能力有明确边界：当前接入的是公开 HTTPS 文本、HTML、JSON，以及配置后可用的 Brave 搜索。上游 Tauric 专用行情、财报、宏观数据库、DCF/风险计算引擎、长期投资决策追踪均未接入。缺数据时应交付缺口与计算口径，不能宣称调用了这些工具。原有共享 SDK、总并发上限和项目隔离机制继续使用。

## 本机怎么试

已有安装运行以下命令；没有安装则先按 setup 流程完成模型和工作台配置：

```bash
node scripts/team-pack.mjs install team-packages/investment-lab
node scripts/team-pack.mjs install newtype
```

确认没有项目正在执行后重启服务，再打开工作台的“团队与项目”（默认 `http://127.0.0.1:4870/teams`）。

1. 点“新项目”，选择“观澜 · TradingAgents 投研团队 2.0.1”。
2. 选择“五角色协作演示（虚构公司）”，保留“本机工作台”，开工。
3. 查看研究范围并确认，检查各专家产物与反方意见，最后验收报告。示例数字全部为合成数据，只验证方法与协作。
4. 测真实效果时选择“真实公司研究”，把公司、日期、问题和公开原始资料 URL 填完整。检查结论是否能追溯到事实，不能只看报告是否写得流畅。
5. 内容团队选择“文枢 1.0.1”，可从编辑已有短文开始；也可给公开来源和写作目标，让副主编选择研究、核查、起草、编辑等任务。确认后资料管理员在当前项目归档。

新项目默认显示各包最新语义版本；历史项目仍用原摘要，旧投研不会被静默迁移。同版本多个内容摘要会分别显示。飞书项目仍需为对应角色绑定机器人，可复用已有可用机器人；本轮本机试跑不要求重新扫码。

验收时看三个地方：**交付文件**是否完成你的目标，**协作计划**是否体现专业交接，**来源与确认记录**是否支持交付中的事实与审阅声明。工作台的确认代表流程动作，不能自动证明某个真人已阅读全文。

## 来源与确认记录

- 成功抓取由宿主保存文本、URL、抓取时间、摘要及 sourceId，放在项目 `context/source-ledger.jsonl` 和 `context/sources/`。角色只读这些文件。搜索摘要和已读全文分开记录。
- 确认事件由编排写 `context/approvals.json`，记录关口、动作、操作者、入口、时间。归档角色据此说明确认来源；缺记录就说明未知。
- Newtype 保留上游 SUL-1.0 声明与既有许可来源说明，通过安装器下载到本机。它不属于平台 MIT 内容，也不因本次补充而变成 Apache 或 MIT。

## 作者复现

TradingAgents 适配不执行上游安装器。取固定提交的 checkout 后，可在空目录重建同一包：

```bash
node scripts/adapt-tradingagents.mjs <TradingAgents-checkout> <空输出目录>
node scripts/team-pack.mjs validate <输出目录>
node scripts/team-pack.mjs verify-export <输出目录>
node scripts/team-pack.mjs export <输出目录> investment-lab-2.0.1.team.json
```

重建脚本从固定提交读取 Git blob，checkout 中的未提交修改不会混入包。其他团队作者仍使用 `skills/team-packager/SKILL.md`，保留上游方法、明确未适配能力，不只换角色名。

### 对抗复核发现与修正

1. **研究范围自造任务表**：首轮主理人看不到完整团队目录，范围文件列出与实际目录不一致的任务和并行关系。平台现将真实角色、技能、任务依赖一起提供，要求范围阶段不自造计划。新会话实测已只写目标、问题、证据、缺口与限制；实际执行仍由原声明式计划控制。
2. **量化计数与复杂统计错误**：首轮把四个区间中的两次跑赢写成三次，基准月度样本波动也出现误差。2.0.1 对表现比较要求逐行算收益、判真值、累加次数；无计算引擎时复杂统计列为待复核。定向实测结果为 2/4、50%，区间收益 20% 对 4%，超额 16 个百分点，与独立算式一致。
3. **调用尝试可能被误当成功**：原运行门槛只看 Skill 进度事件。现改为只认 SDK 成功钩子；“有文件、只有尝试”的反例已被测试拒绝，真实加载回执已验证。
4. **旧角色绑定混入新版**：新版只锁定自身声明的角色绑定；退役角色的机器人可给新角色复用，既有项目绑定不变。离线反例通过。
5. **自动确认冒充真人**：本轮内容归档准确写出 `Codex 自动回测（非人工验收）`、`automated-test`、关口和时间，并说明不构成真人逐字审阅。终稿与归档都保留两次实际网页读取记录，和平台台账相符。
6. **取消新建后带入上个团队的目标**：新建表单重开时重置，Chrome 已验证内容目标不会带入默认投研团队。

投研 **2.0.1 并未重复全量运行十六任务**：与完成全量链路的 2.0.0 比较，只改变 `manifest.json` 和表现比较 Skill，角色、工作流、其他十五个 Skill 内容不变；变化项已单独真实复测。首轮失败产物保留，不能用修订后的定向成功覆盖其原始问题。新示例用于用户再测真实效果，调用通过不等于数值和结论无需复核。

Grok 的测试执行与 23 项通过结论已留档；其后源码快照审查运行约 8 分钟未返回结论，辅助进程已停止，**没有将其记为 Grok 审查通过**。以上最终对抗复核由 Codex 对照代码、工具结果和产物完成。

### 复现本轮任务

投研：使用随包虚构青禾软件数据，要求规划阶段选择全部十六个声明任务，每项实际调用 Skill；不适用或缺数据也要说明适用边界，不编造行情。确认研究范围后运行至报告确认。

内容：使用 TradingAgents 固定提交 README 作为唯一公开来源，写约 500 字的《开源投研团队怎样协作》。提供两条明确标为合成材料的采访观点：“先明确交付和交接，再按问题选择角色”“配置角色保证十倍效率，但未提供数据”。要求八角色完成知识盘点、提取、研究、核查、起草、编辑、复核、汇总，确认后归档，区分事实、观点和缺口。

本轮 28 次全流程调用及 3 次定向调用均使用真实模型；输入为合成测试资料及公开固定来源，关口由自动回测操作，**不包含新团队真实飞书全流程、多位真人验收、投资绩效或生产级行情/计算服务验证**。Grok 没有读取密钥、操作真实飞书或修改源码。原始私有证据位于本地 `本地资料/2026-11-27-开源团队适配/`，不随公开包分享。
