# 飞书 AI 团队 · 版本导航

给用户和 coding agent 的共同入口。先问想搭什么，再选择版本。这里的“版本”是功能组合；实际代码版本以 Git 提交为准，所有可用组合都从 `main` 安装。

## 当前可用

| 名称 | 定位 | 能得到什么 | 安装提示词 | 配置标识 |
| --- | --- | --- | --- | --- |
| **启航版** | 单群入门 | 一个团队群、三个 AI 同事、管理员助手、网页工作台；原群内逐个推进项目 | [启航版](prompts/basic.md) | `basic` |
| **领航版** | 多项目协作 | 启航版的流程与角色，加独立项目群、项目与角色上下文隔离、并行任务、发起人确认，历史项目保留原确认权限 | [领航版](prompts/projects.md) | `projects` |

两版都按“澄清 → PRD → 设计 → 开发 → 走查 → 验收”运行，都以单文件静态网页为交付。选择领航版不会自动获得后端、数据库或跨设备业务数据同步。

上面描述的是默认网页团队。**团队包是独立于版本的能力选择**：筑页（网页）、观澜（投研）、文枢（Newtype 内容），以及第三方自定义团队，分别遵循包内的协作流程和交付标准。见 [团队包搭建提示词](prompts/ecosystem.md)。本机体验可保留当前模式；团队包独立群使用包内角色创建。不要因为出现新团队而删除已有版本提示词或强迫基础用户升级。

## coding agent 的第一轮

用户只给本仓库链接、说“搭起来”，或没有明确功能范围时，先问：

> 你想搭哪一种？启航版是在一个群里完成网页协作，适合先体验；领航版会给每个项目建独立群，每个项目分别确认。你更需要哪种？

回答“不需要多项目”“先基础版”“单群就够”时，用启航版；回答“多个项目”“独立群”“并行协作”时，用领航版。已明确选择或只是维护已有安装时，不重复提问。不要默认让入门用户配置人员名册。

选择后先阅读对应完整提示词，再执行 `node setup.mjs mode basic` 或 `node setup.mjs mode projects`。这个命令只保存选择，不创建机器人。按提示运行 setup 完成安装。首次配置默认启航版；旧安装没有选择字段时，程序按是否已有独立项目保留原行为。已有领航项目的目录不能降为启航版，以免失去分工权限。

## 保留与扩展约定

- 现有提示词长期保留；新增版本增加独立文档，在上表注明定位、运行配置、验证范围和升级路径。
- 未来版本未实现前不列入“当前可用”，不提前承诺功能。
- 共用的安装、密钥、单实例和调试步骤统一放在[复现指南](复现指南.md)，各版只补差异与验收。
- 每版记录已测与未测范围，不能把另一版的实测当成本版实测。
- `learn` 分支与[历史动手路线](动手搭建.md)继续保留，适合学习从零实现；不用于安装当前版本。
