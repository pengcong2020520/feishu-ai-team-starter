# 完整应用团队：从规格到上线

## 已实现的本机版本

新增「筑域 · 应用开发团队」，交付前端、HTTP 后端、SQLite 数据库、迁移、自动测试和本机运行地址。原「筑页」单文件网页团队保留，旧项目继续锁定原团队包。这支团队由五个新角色组成，需单独连接五位飞书机器人；只在本机试用可先不扫码。

平台的 `application` 契约目前支持 `node24-sqlite`。角色只写自己负责的工作区；运行器在每个项目的容器中执行版本化 SQL 迁移和 `node --test`，发布后通过 HTTP 健康检查才展示入口。生成的测试和部署 JSON 会被平台真实回执覆盖，不能靠 Agent 声称通过。旧网页团队仍按原 workflow 执行。

## 角色与交接

| 角色 | 负责什么 | 主要交付 |
| --- | --- | --- |
| 产品经理（协调者） | 澄清目标、用户流程、验收标准，维护需求变更 | `spec.md`、验收场景 |
| 设计师 | 交互与视觉方案，明确页面状态 | 原型、设计说明 |
| 架构师 | 技术方案、数据模型、API 契约；实现后独立审查 | `plan.md`、数据模型、架构审查 |
| 程序员 | 前后端、数据库迁移、自动化测试、缺陷修复 | 可运行源码、迁移、测试 |
| 测试与部署工程师 | 启动隔离环境，验证端到端场景，执行受控部署并复测 | 测试报告、部署记录、线上冒烟 |

架构设计和架构审查由**同一个架构师角色在不同节点**完成，复核节点开新会话。程序员先作为全栈角色。审查失败进入修复 → 重新复核 → 重新测试。

## 工作流

项目级原则和技术选型写入团队包的 `constitution.md`，作为版本化团队知识。每个项目按下面的顺序运行，Spec Kit 步骤与平台关口一一对应；不在群里直接执行任意 CLI 命令。

1. **澄清与 Specify**：产品经理写需求、用户故事和可验证的成功标准；人确认需求。
2. **Plan**：架构师写前端、后端、数据库、API、运行环境和迁移方案；设计师补齐交互。人确认技术方案与界面。
3. **Tasks**：把规格拆为实现任务和测试场景；任务清单保留在项目工作区。
4. **Implement**：程序员完成源码和测试；每个任务保留变更、运行结果与关联规格。
5. **Converge**：架构师只读核对规格、API、数据模型和实际实现；不通过时回到对应实现任务。
6. **Test**：平台在隔离容器里执行迁移与 `node --test`。测试文件可覆盖 HTTP、数据库与前后端集成；失败回修，测试不会自动变成通过。浏览器 E2E 目前需由团队交付额外测试工具，平台内置回执不声称已跑浏览器。
7. **Deploy**：真人确认发布关口后，平台在本机 Docker 运行应用，健康检查通过才切换入口；失败重启上一版并等待其恢复。当前没有服务器远端部署适配。
8. **Accept**：展示运行地址、功能场景、数据持久化、测试与部署结果，由用户完成最终验收。

Spec Kit 的 `specify → plan → tasks → implement → converge` 是方法与产物模板；角色调度、确认、重试及版本锁继续由本项目的团队包引擎执行。Bug 修复走独立的「复现 → 修复 → 回归 → 重部署」回路，不重新生成整份需求。

## 运行范围

- 准备 Node.js 24+ 与可用的 Docker daemon。macOS 可使用 Colima。容器使用 `node:24-bookworm-slim`；首次执行需能拉取镜像。Docker 不可用时测试节点报错并停下。
- 应用源码限项目 `app/`；不接受软链接、隐藏文件或 `node_modules`，总量不超过 20 MB。运行容器限制 CPU、内存、进程和写入目录；测试容器禁用网络，发布容器仅把应用端口映射到本机 `127.0.0.1`。发布容器使用 Docker bridge，应用代码仍可发起网络连接，因此安装外部团队包时应信任其作者。
- 每项目独立数据库。递增的 `NNN.sql` 迁移只应用一次；新版发布前复制上一版数据库，失败回滚继续使用上一版数据库。已运行过的迁移文件不应修改。
- 应用的 `/health`、运行地址、测试回执和部署回执分别可从工作台与项目文件查看。应用容器设置 Docker 的 `unless-stopped` 重启策略；电脑关机或 Docker 停止时不会在线。
- 平台不会执行包作者提供的任意 shell 命令，不提供通用 npm 安装、PostgreSQL 或远端发布。需要这些能力时应扩展受控运行器和协议，而不是只改角色提示词。

## 安装与本机回归

```bash
node scripts/team-pack.mjs validate team-packages/app-studio
node scripts/team-pack.mjs verify-export team-packages/app-studio
node scripts/team-pack.mjs install team-packages/app-studio
RUN_APP_LIVE=1 node --test test/app-studio-live.test.mjs
```

最后一条本机回归用[读书会示例](../examples/app-studio-demo/app/server.mjs)创建**隔离测试项目**，走五角色任务节点、人工关口模拟、一次架构打回、实际容器迁移与测试、本机发布、HTTP 表单 API、数据持久化、故意失败的新版健康检查及回滚。测试替身只代替模型生成文件；容器、数据库和 HTTP 是真实运行。此回归不连接飞书，也不代表真人批准。要在飞书里使用，先按开放团队包提示词完成基础 setup，再运行 `node scripts/team-pack.mjs bots app-studio`，逐个扫码连接五个新机器人。真实模型与飞书群链路需在该安装中另行实测。
