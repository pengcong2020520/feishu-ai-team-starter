# 使用 AI 管理员助手

在飞书中私聊「AI 管理员助手」。首次扫码创建它的人是管理员。

## 查看状态与恢复任务

发送“状态”查看团队运行情况和项目进展。项目停下时点“接着做”；团队服务停了时点“重启团队服务”。

也可以直接描述问题，例如“看一下报名页项目为什么停下了”。

## 调试自己的团队包

在同一个私聊里，从已安装团队复制个人版本，或直接发送 `.team.json` 附件、固定提交的 GitHub 包目录链接。例如：

> 复制文枢，做一套“我的产品观察”。保留八个角色，让作者面向独立开发者写作；调整写作 Skill，在工作区加入栏目模板，再按我的要求修改协作流程。先给我看修改摘要。

管理员会在个人草稿里修改 Agent、Skill、workflow 和 workspace 模板，保留原包的来源和许可。原团队与已有项目继续使用原版本。

然后给一个真实任务：

> 用这个草稿试跑：根据我提供的产品材料，写一篇 800 字文章。结束后发我过程和成品。

试跑使用当前模型和同一套编排，会消耗模型额度。它有独立项目、工作区和会话；人工关口由测试驱动模拟，记录中会明确标注。管理员先回消息，后台继续执行，结束后发结果卡。卡片里的“↗ 试跑过程与成果”可以查看角色、实际调用的 Skill、文稿与失败原因。

需要调整时直接说“看一下这次试跑哪里失败，修改后再跑一次”，或者“停下这次试跑”。修改后的草稿必须重新试跑，旧结果不能用于应用新版。

如果只是接口故障或超时，草稿未改，可以点“继续试跑”或直接说“从失败节点继续”。已经完成的研究和文稿会保留，失败记录也能查看。

满意后说“应用这个团队版本”，或点结果卡的“应用这个版本”。新版会出现在工作台团队目录里，新项目可以选择；已有项目不切换。复制为新团队后，需要在工作台通过标准扫码流程连接它自己的机器人。修改同一个团队的新版本继续保留原角色绑定；新增角色仍需连接。

以后继续调整这个个人团队，管理员会从它的最新版本建立新草稿，并自动递增版本号；已经应用的版本保持不变。

说“导出这个团队包”，就能收到 `.team.json` 文件。导出会重新导入核对完整性，包含角色、技能、流程、模板及许可，不包含项目讨论、账号配置或运行记录。别人可以把文件发给自己的管理员助手导入草稿，再试跑、应用和连接机器人。未应用的草稿也可以导出，文件分享不会自动发布到 GitHub。

管理员机器人需要 `im:resource`（获取与上传图片或文件资源）处理附件，新安装扫码会申请。旧机器人若提示缺少该权限，在飞书开放平台给管理员应用补充并发布即可，无需重建机器人。

## 调整原网页团队与服务代码

原网页团队的 `prompts/` 和 `team-skills/` 仍使用工作副本修改：文字检查通过后生效，代码在卡片上点“上线”后应用。已安装团队包使用上面的草稿与版本流程，不能通过修改原网页提示词更新。

改完想恢复，可以点“撤销这次改动”，也可以私聊发“撤销”。
