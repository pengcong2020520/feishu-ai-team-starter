# 可执行配图格式

只有正式 Markdown 交付使用以下围栏；普通代码示例用四个反引号包住，平台不会把示例中的定义当图片执行。已有专业 Skill 不允许附图或限制篇幅时，遵守专业约束。

## 顺序流程

```team-figure
{
  "kind": "flow",
  "title": "从资料到可确认的成果",
  "steps": [
    {"name": "确定问题", "note": "明确读者、范围和这次需要决定的事"},
    {"name": "组织证据", "note": "按照专业大纲整理来源、推导与缺口"},
    {"name": "阅读与确认", "note": "先看结论与关键图，再按原关口确认"}
  ],
  "caption": "图帮助读者理解处理顺序；正式确认仍沿用项目的工作流。",
  "source": "来源：本项目文档规范"
}
```

顺序流程限 2–6 步；步骤名不超过 24 字，说明不超过 52 字。存在判断分支、并行或复杂角色关系时，不可用顺序图伪装；先用清楚的表格或已有关系图。

## 同口径比较

```team-figure
{
  "kind": "bar",
  "title": "三支内置团队的角色数量",
  "unit": "位",
  "data": [
    {"label": "筑页", "value": 3},
    {"label": "观澜", "value": 5},
    {"label": "文枢", "value": 8}
  ],
  "caption": "这里比较的是角色数量，不代表质量、并发量或资源占用。",
  "source": "来源：筑页 1.0.0、观澜 2.1.0、文枢 1.0.1 的团队定义"
}
```

比较限 2–8 项、同一单位、有限非负数；从 0 起算，保留输入次序。负值、区间、误差、时间序列或不同比例单位请先用数据表，不擅自改成适合图形的数字。数字必须已在正文或材料中给出，来源说明无法证明真实性，仍要按研究 Skill 核实。

共同字段：title ≤36 字、caption ≤140 字、source ≤100 字，均为非空单行。每份文档最多 8 张图，单图最多 8 MB，图片会冻结到该项目的发布缓存；正文和图片任一变更都视为新版本。图注与来源作为正常段落保留在图片下方。

平台不执行 Mermaid、任意 HTML/SVG、网络脚本或图片下载。它只将上述有界数据画成图。缺少 Chrome/Chromium 时同步报出配图错误，原项目流程和产物保留；安装时按仓库既有浏览器要求处理。
