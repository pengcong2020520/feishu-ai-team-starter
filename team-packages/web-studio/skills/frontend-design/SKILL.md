# 有设计意图的成品网页

改编自 learn-codex-harness 的 frontend-design（其原型来自 anthropics/skills 的 frontend-design，Apache-2.0）。保留"以产品、受众和任务决定视觉取舍，避免套用模板化 AI 风格"的方法。

## 输入与边界

先读 docs/prd.md、design/wireframe.html（含 design-outline 大纲）和 design/theme.json，输出 site/index.html。

| 可以直接优化 | 不能改 |
|---|---|
| 字体、间距、控件样式、状态样式、图标、微交互 | 区块拆分或合并、字段分组、按钮位置、操作去向、功能增删 |

确实需要改结构时不要改，在最后的回复里提出来，交给用户决定。PRD 里的每个状态都要能通过真实操作到达（填写、点击）。

## 状态直达

走查页会把网页嵌进来，用地址 `#state=<状态 id>`（PRD 和线框里的状态 id）直接打开每个状态：
- 首次加载和 hashchange 都要处理；按状态用示例数据把页面摆成那个样子（例如报满就当作已有 30 人报名，校验失败就填好错误的值并显示错误提示）；
- 直达只用来演示，不写入本地存储；没有 hash 或是未知状态时正常打开；
- 走查页里的网页运行在隔离的框里，那里不能用本地存储：所有 localStorage 读写都包在 try/catch 里，失败时退回内存，页面照常可用。

## 先想清楚，再动手

1. **短设计计划**：用真实内容、受众和任务决定颜色、字体分工、对齐与层级，以及一个最值得强调的特征。写成 site/index.html 开头的一段 HTML 注释（3–5 行），方便检查。
2. **对照需求自查，再实现**：每个视觉选择都要能解释为什么适合这个页面。没有用户依据时，避免惯性的紫色渐变、奶油底配衬线标题、黑底荧光色、报纸细线布局、整页同样圆角的卡片、装饰性编号和每节重复的淡入动效。

## 视觉与文案

- 严格使用 design/theme.json 的令牌：写成 CSS 变量，颜色、字号、圆角、间距、阴影都从变量取。
- 字体用一到两个有分工的系统字体栈，以字重、字号、行高和留白形成层次；正文行长控制在约 40 个汉字以内。
- 视觉重点集中在最能表达这个页面的地方，其余部分保持克制。
- 用户操作触发的微交互要解释状态变化；自动播放的动效要少，并尊重"减少动态效果"的系统设置。
- 键盘焦点清晰可见、对比度足够；电脑（1280 宽）和手机（375 宽）都好看，响应式不能悄悄改变按钮关系。
- 文案帮用户完成任务：按钮写具体动作，错误说清问题和怎么改，空状态给出下一步。保留 PRD 的真实文案，不编造功能或数据来装饰页面。

## 实现

- 单文件：HTML、样式和少量原生 JavaScript 写在一起；不引用任何外部资源（字体、图片、图标库、CDN），图标用内联 SVG 或 emoji。
- 需要保存的数据用浏览器本地存储（localStorage）模拟，并在注释里写明这是演示；读写按上面"状态直达"的要求包好。
- 篇幅控制在 400 行以内，一次写完整个文件，不要分多次小改；只写 site/index.html，不建其他文件。
- 写完后逐条对照 PRD 的功能需求和成功标准读一遍代码，不满足就改。

最后的回复：一句话说明设计重点和是否满足全部成功标准，不超过 60 字。
